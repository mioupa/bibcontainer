## 1. 背景と目的

### 1.1 現状

現在は Windows 用フリーソフト「私本管理Plus」（Ver 12.3.0、2026-06）で蔵書を管理している。不満点は次のとおり。

- UI が古い。
- Windows 専用で、Mac では使えない。
- データが PC 内に閉じており、複数の PC で共有できない。

私本管理のデータは移行しない。新アプリでゼロから登録し直す。

### 1.2 私本管理の「2段バーコードで自動入力」の仕組み（調査結果）

私本管理では、本の裏表紙のバーコードを 2 段とも読むと、書誌情報・書影・価格・ジャンルが自動で入る。調査の結果、仕組みは次の 2 つに分かれていた。

| 段 | 中身 | 私本管理での処理 |
|---|---|---|
| 1段目 | ISBN-13（`978…` / `979…`） | ISBN をキーに、取得元プラグイン（DLL）で外部サイトを検索する。Amazon.co.jp プラグインは Amazon の公式 API（旧 PA-API v5、2026年5月以降は後継の Creators API）を使用。ほかに楽天ブックス、honto、e-hon、Webcat Plus のプラグインがある。 |
| 2段目 | `192` + Cコード4桁 + 本体価格5桁 + チェックデジット | API は使わない。バーコードの数字を分解して、Cコード（販売対象・発行形態・内容）と本体価格（税抜）を得ている。 |

このため新アプリでは、次の 2 つを作れば同等のことができる。

- 2段目のデコード処理（完全にオフラインで動く）
- 取得元を差し替えられる書誌取得の仕組み

**Amazon について**: Creators API を使うには、自分の Amazon アソシエイトアカウントが承認済みで、かつ直近 30 日間に 10 件以上の紹介販売実績が必要である。取得データの保存にも規約上の制約がある。個人の蔵書管理で常用するのは難しいため、標準の取得元にはせず、資格を満たした場合に使える任意の取得元として実装枠だけ用意する。他人のプラグインから認証情報を抜き出して流用する方法は、規約違反なので採らない。

### 1.3 目的

- macOS と Windows で同じように使える、見やすい蔵書管理アプリを作る。
- 2段バーコードのスキャンで、書誌情報・書影・価格・ジャンルを自動入力する。
- Google Drive の同期フォルダを介して、複数の PC で同じ蔵書データを使う。サーバは立てない。

## 3. スコープ

### 3.1 対象

- ISBN のある書籍（単行本、文庫、新書、コミック、ムックなど）の登録・管理
- ISBN のない本（同人誌、古書など）の手動登録
- 読書記録、購入情報、欲しい本リスト
- 複数 PC 間のデータ同期

### 3.2 対象外（初版）

- 雑誌（`491` で始まる定期刊行物コード）、一般 JAN 商品（CD・DVD・ゲーム等）
- 電子書籍の管理
- 貸出管理
- 複数ユーザーでの共有、権限管理
- Web 版
- 私本管理からのデータ移行（汎用 CSV インポートは別途用意する）

### 3.3 将来対応（設計で考慮する）

- iOS／Android 版（Tauri 2 のモバイル対応を想定）。スマホのカメラでのスキャン、書店での所持確認
- 同期方式の追加（Google Drive API への直接接続、WebDAV など）

## 4. 利用環境と前提

- **端末**: Mac mini（常時稼働）、MacBook Air、Windows PC。複数台で同時に起動することがある。
- **OS**: macOS 13 以降（Apple Silicon）、Windows 11（WebView2 は標準搭載）。Windows 10 は動けばよい。
- **ネットワーク**: 書誌取得以外の機能はすべてオフラインで動くこと。
- **同期**: Google Drive for desktop で同期されたフォルダを使う。
  - Mac の例: `~/Library/CloudStorage/GoogleDrive-<アカウント>/マイドライブ/…`
  - Windows の例: `G:\マイドライブ\…`（ストリーミングモード）。ミラーリングモードの場合はユーザーフォルダ配下になる。
- **バーコードリーダー**: キーボードとして動作するもの（HID モード）。数字列の後に Enter（または Tab）を送る。
- **UI 言語**: 日本語のみ。ただし文字列は 1 か所にまとめ、将来の多言語化に備える。

| フォーム | react-hook-form + zod | |
| IPC の型 | tauri-specta または ts-rs | Rust の型から TypeScript の型を自動生成する |
| DB | SQLite（rusqlite、bundled）、WAL モード、FTS5 | ローカル専用。同期フォルダには置かない |
| HTTP | reqwest（rustls） | |
| XML | quick-xml | NDLサーチの応答解析用 |

## 7. 機能要件

### 7.1 書籍データの管理（FR-BOOK）

- **FR-BOOK-01 [MUST]** 書籍を登録・編集・削除できる。削除はまず「ゴミ箱」に移し、ゴミ箱から復元・完全削除できる（同期のため、完全削除後も削除記録は残す）。
- **FR-BOOK-02 [MUST]** 管理項目は「8.1 エンティティ」のとおり。基本項目に加え、読書記録・購入情報・所有状態を持つ。
- **FR-BOOK-03 [MUST]** ISBN のない本も手動で登録できる（ISBN は空欄可）。
- **FR-BOOK-04 [MUST]** 所有状態は「所有」「欲しい本」「手放した」の 3 種類。[SHOULD] 「手放した」は売却・譲渡した本の履歴として残すためのもの。
- **FR-BOOK-05 [MUST]** 保管場所を階層（例: 自宅 > 書斎の本棚 > 3段目）で管理できる。
- **FR-BOOK-06 [MUST]** タグを複数付けられる。タグ名の `/` は階層表示に使う（例: `研究/SiC`）。
- **FR-BOOK-07 [MUST]** シリーズと巻次を管理できる。巻次は文字列（「上」「3」「第2部」など）で持ち、並べ替え用の数値を別に持つ。シリーズ名は取得元のシリーズ情報から候補を出す。
- **FR-BOOK-08 [MUST]** 複数の書籍を選んで、保管場所・タグ・所有状態・読書状況などを一括変更できる。
- **FR-BOOK-09 [MUST]** 各項目の値がどこから来たか（バーコード、openBD、NDL、手入力など）を記録する。取得元ごとに値を消したり再取得したりできるようにするため。
- **FR-BOOK-10 [COULD]** 同じ本を 2 冊以上持つ場合は、別レコードとして登録する（重複警告の後に確認して登録）。

### 7.2 バーコード入力（FR-SCAN）

#### 判定

- **FR-SCAN-01 [MUST]** 読み取った数字列を次のように判定する。

| 先頭 | 桁数 | 判定 | 扱い |
|---|---|---|---|
| `978` / `979` | 13 | ISBN-13（書籍 JAN 1段目） | 書誌取得のキー |
| `192` | 13 | 書籍 JAN 2段目 | Cコードと本体価格を取り出す |
| `491` | 13 | 雑誌コード | 「雑誌は非対応です」と表示 |
| 上記以外 | 13 / 8 | 一般 JAN | 「書籍以外は非対応です」と表示 |
| — | 10 | ISBN-10（手入力を想定。末尾 `X` 可） | ISBN-13 に変換して扱う |

- **FR-SCAN-02 [MUST]** チェックデジットを検証し、不一致なら受け付けずに警告音を鳴らす。
  - EAN-13（ISBN-13 と 2段目）: 左から 12 桁に重み 1, 3, 1, 3… を掛けて合計し、`(10 − 合計 mod 10) mod 10` がチェックデジット。
  - ISBN-10: 左から 9 桁に重み 10〜2 を掛けて合計し、`(11 − 合計 mod 11) mod 11` がチェックデジット（10 のときは `X`）。
- **FR-SCAN-03 [MUST]** 2段目は次のように分解する。
  - 4〜7 桁目: Cコード（1 桁目: 販売対象、2 桁目: 発行形態、3〜4 桁目: 内容）。名称は付録 A の表で引く。表にないコードは「未定義（xx）」と表示し、内容の大分類（3 桁目）だけを使う。
  - 8〜12 桁目: 本体価格（税抜、円）。`00000` は非再販本または 10 万円以上を意味するので、価格は「不明」として空にする。
- **FR-SCAN-04 [MUST]** ISBN-10 と ISBN-13 を相互に変換できる（`979` で始まるものは ISBN-10 にならない）。表示は既定でハイフンなしとする。

#### 2 段のペアリング

- **FR-SCAN-05 [MUST]** 1 冊につき「1段目 → 2段目」の順で読むのが基本だが、逆順でも同じ本として扱う。状態遷移は次のとおり。

```
待機中
  ├─ ISBN を読む  → 「ISBN 保留」へ。この時点で書誌取得を開始する（2段目を待たない）
  └─ 2段目を読む  → 「2段目 保留」へ（逆順スキャン）

ISBN 保留（タイムアウト T 秒）
  ├─ 2段目を読む        → この本に 2段目を付けて確定 → 待機中
  ├─ 別の ISBN を読む   → 保留中の本は 2段目なしで確定し、新しい ISBN で「ISBN 保留」
  ├─ 同じ ISBN を読む   → 二度読みとみなして無視（注意音）
  └─ タイムアウト／確定キー → 2段目なしで確定 → 待機中

2段目 保留（タイムアウト T 秒）
  ├─ ISBN を読む   → ペアにして確定 → 待機中
  ├─ 2段目を読む   → 古い 2段目を捨てて新しいものを保留（注意音）
  └─ タイムアウト  → 2段目を捨てる（エラー表示）→ 待機中
```

- **FR-SCAN-06 [MUST]** タイムアウト T の既定値は 10 秒。設定で 3〜30 秒に変更できる。

#### 入力の受け付け方

- **FR-SCAN-07 [MUST]** スキャン登録画面では、入力欄にフォーカスがなくても数字列＋Enter（または Tab）を受け付ける。
- **FR-SCAN-08 [MUST]** 日本語入力（IME）がオンでも正しく読めること。入力欄の値ではなく `KeyboardEvent.code`（`Digit0`〜`Digit9`、`Numpad0`〜`Numpad9`、`Enter`、`Tab`）でキーを拾い、既定の入力動作を止める。手入力欄では全角数字を半角に正規化する。
- **FR-SCAN-09 [MUST]** メイン画面の検索欄で ISBN を読んだ場合は、その本の詳細へ移動する（未登録なら登録するか確認する）。
- **FR-SCAN-10 [SHOULD]** メイン画面でテキスト入力欄にフォーカスがないとき、キー間隔が閾値（既定 30ms、設定可）以下の数字列＋Enter をスキャンとみなし、スキャン登録に引き渡す。
- **FR-SCAN-11 [MUST]** 結果を音と画面表示で知らせる。音は 3 種類（成功、エラー、重複・注意）で、音量の調整とミュートができる。
- **FR-SCAN-12 [MUST]** バーコードリーダーの末尾キー（Enter／Tab／なし）と、先頭・末尾に付く余分な文字の除去を設定できる。

#### 登録の流れ

- **FR-SCAN-13 [MUST]** 「1 冊ずつ登録」モード: ペアが確定すると、取得結果を入れた編集フォームが開く。内容を確認して保存する。
- **FR-SCAN-14 [MUST]** 「連続登録」モード: 次々にスキャンすると、画面の一覧に本が溜まっていく。書誌取得は裏で並行して進め、各行に状態（取得中／完了／一部取得／取得失敗／重複）を表示する。最後に一覧を確認して「まとめて保存」する。保存前に行の編集・削除ができる。
- **FR-SCAN-15 [MUST]** 連続登録では、全冊に共通で入れる値（保管場所、タグ、所有状態、購入日、購入店）を先に指定できる。
- **FR-SCAN-16 [MUST]** オフラインのときや取得に失敗したときも、ISBN と 2段目の情報だけで保存できる。その本は「取得待ち」として、オンラインに戻ったら自動で再取得する。

#### 重複チェックと欲しい本

- **FR-SCAN-17 [MUST]** スキャンした ISBN が「所有」で登録済みなら、警告音を鳴らし、書名と保管場所を表示する（例:「所有済み: ○○ ／ 書斎の本棚 3段目」）。
- **FR-SCAN-18 [MUST]** 「欲しい本」に登録済みなら、「所有に移しますか？」と確認する。移す場合は購入日に今日の日付を入れる。
- **FR-SCAN-19 [SHOULD]** 手動登録では、ISBN の一致に加えて、書名・著者が似ている本があれば候補として表示する。

#### カメラ読み取り

- **FR-SCAN-20 [COULD]** PC のカメラ（Mac の連係カメラで iPhone を使う場合を含む）で EAN-13 を読み取る。読み取った数字列は、リーダーからの入力と同じ処理に渡す。macOS では Info.plist に `NSCameraUsageDescription` を設定する。

### 7.3 書誌情報の自動取得（FR-META）

#### 取得元（Provider）

- **FR-META-01 [MUST]** 取得元はプラグイン的に追加できる構造にする。Rust のトレイトとして、次の機能を定義する。
  - ISBN で 1 件取得する（必須）
  - 書名などのキーワードで候補を検索する（任意）
  - 複数 ISBN をまとめて取得する（任意）
  - 能力情報: 必要な認証情報、取れる項目、レート制限、クレジット表記の文言
- **FR-META-02** 実装する取得元は次のとおり。詳細は「11. 外部 API メモ」を参照。

| 取得元 | 優先度 | 認証 | 主に取れる情報 |
|---|---|---|---|
| openBD | [MUST] | 不要 | 書名、著者、出版社、発行日、価格、**Cコード**、内容紹介、書影（Cコード・内容紹介・書影は版元ドットコム会員社の本のみ。それ以外は NDL 由来の簡易な書誌） |
| NDLサーチ（SRU） | [MUST] | 不要（継続利用は届出を推奨） | 書名とヨミ、著者、出版社、発行年、価格、ページ数・大きさ、**NDC**、シリーズ、巻次 |
| Google Books | [MUST] | API キー（ユーザーが入力。キーなしでは使えない） | 書名、著者、内容紹介、ページ数、書影、言語 |
| Open Library | [SHOULD] | 不要 | 書名、著者、出版社、発行日、ページ数、言語、内容紹介、書影（主に洋書。和書はほとんど収録がない） |
| 楽天ブックス | [SHOULD] | アプリ ID とアクセスキー（ユーザーが入力） | 書名・著者のヨミ、判型、税込価格、内容紹介、大きい書影 |
| Amazon Creators API | [COULD] | 認証情報（ユーザーが入力）と利用資格 | 書名、著者、書影など。規約上の保存制限に従う（13章） |

NDLサーチの書影 API は使わない。公式の API 仕様書に記載がなく、NDL サーチ自身のページ以外からの参照（Referer）は 403 で拒否されるため（2026-10 確認、ユーザー判断）。

Open Library は、Google Books の ISBN 検索が 2026-10 初めから 0 件を返す障害を受けて、洋書の書誌と書影を補うために加えた（2026-10 ユーザー判断。`docs/decisions/0017`）。

- **FR-META-03 [MUST]** 取得元ごとに有効・無効を切り替えられる。認証が必要な取得元は、キーが設定されたときだけ有効にできる。

#### 統合（マージ）

- **FR-META-04 [MUST]** 1 冊について、有効な取得元に並行して問い合わせ（取得元ごとのレート制限は守る）、項目ごとに優先順位に従って値を選ぶ。優先順位は、ISBN が 978-4 で始まる本（和書。ISBN のない本も含む）と、それ以外の本（洋書など）の 2 組を持つ。既定の優先順位は次のとおりで、設定画面で組ごと・項目ごとに並べ替えられる。

| 項目 | 和書（978-4、ISBN なし） | 洋書など（それ以外） |
|---|---|---|
| 書名・副書名 | openBD > NDL > 楽天 > Google > Open Library | Google > Open Library > NDL > openBD > 楽天 |
| 書名のヨミ | NDL > 楽天 | 同じ |
| 著者（役割付き） | openBD > NDL > 楽天 > Google > Open Library | Google > Open Library > NDL > openBD > 楽天 |
| 出版社 | openBD > NDL > 楽天 > Google > Open Library | Google > Open Library > NDL > openBD > 楽天 |
| 発行日 | openBD > 楽天 > NDL > Google > Open Library | Google > Open Library > NDL > openBD > 楽天 |
| 本体価格 | **2段目** > openBD > NDL（楽天の税込価格は参考値として別に保持） | 同じ |
| Cコード | **2段目** > openBD | 同じ |
| NDC | NDL | 同じ |
| ページ数・大きさ | NDL > openBD > Google > Open Library | 同じ |
| シリーズ・巻次 | openBD > NDL > 楽天 | NDL > openBD > 楽天 |
| 内容紹介 | openBD > 楽天 > Google > Open Library | Google > Open Library > openBD > 楽天 |
| 書影 | openBD > 楽天 > Google > Open Library > Amazon | Google > Open Library > openBD > 楽天 > Amazon |

洋書などの組は、NDL（CiNii 由来）の書名が小文字になり、内容紹介・書影もないため、Google と Open Library を先にする（2026-10 ユーザー判断。`docs/decisions/0020`）。

- **FR-META-05 [MUST]** 編集フォームでは、各項目に「他の取得元の値」を候補として表示し、選び直せる。
- **FR-META-06 [MUST]** 取得した値を正規化する。
  - 前後の空白を除く。英数字と記号は NFKC で半角にそろえる。
  - 著者名の「／著」「訳」「編」などは役割として分離する（例:「山田玲子／著 水野菜生／英訳」→ 山田玲子〔著〕、水野菜生〔英訳〕）。
  - 洋書は NDL の構造化された名前を使い、`名 姓` の形にそろえる（例: `Martin, Robert C.` → Robert C. Martin〔著〕、`foreword by James O. Coplien` → James O. Coplien〔序文〕）。詳細は `docs/decisions/0019`。
  - 日付は `YYYY`、`YYYY-MM`、`YYYY-MM-DD` のいずれかにそろえる。
- **FR-META-07 [MUST]** 一度手で直した項目は、再取得しても上書きしない（上書きするかはユーザーが選ぶ）。

#### 通信の作法

- **FR-META-08 [MUST]** 取得元ごとにレート制限を守る（既定: NDL・Google・楽天・Open Library は 1 秒に 1 件、NDL は並列リクエストをしない）。openBD は複数 ISBN をカンマ区切りでまとめて取得できる（1 回あたり 100 件程度まで）。
- **FR-META-09 [MUST]** User-Agent に、アプリ名・バージョン・連絡先 URL を入れる（例: `bibcontainer/0.1 (+https://…)`）。連絡先は設定で変更できる。
- **FR-META-10 [MUST]** 取得元の生の応答を、ローカルのキャッシュテーブルに保存する（同期はしない。有効期限は既定 30 日）。マッピングを改良したとき、再ダウンロードせずに作り直せるようにするため。
- **FR-META-11 [MUST]** タイムアウトとリトライを設ける（タイムアウト 10 秒、指数バックオフで最大 3 回）。取得元の 1 つが落ちていても、ほかの取得元の結果で登録を続ける。
- **FR-META-12 [SHOULD]** 書名・著者のキーワード検索で候補を一覧表示し、選ぶと登録フォームに反映される（ISBN のない本や、バーコードが読めない本のため）。
- **FR-META-13 [SHOULD]** 登録済みの本を選んで「書誌を再取得」できる（一括も可）。

### 7.4 書影（FR-COVER）

- **FR-COVER-01 [MUST]** 書影は「7.3」の優先順位で取得する。取れなければ、書名と著者を描いた仮の表紙を表示する。
- **FR-COVER-02 [MUST]** 「画像なし」のダミー画像を見分ける。画像でない応答は Content-Type で判定する。Google Books などが返す「No image」画像（Google は寸法の違う 3 種類がある）は、既知のハッシュ値と画像サイズで判定する。
- **FR-COVER-03 [MUST]** 保存する書影は、長辺 800px 以下の JPEG（品質 85 程度）に変換し、EXIF を除く。ファイル名は SHA-256 ハッシュとする（同じ画像は 1 つだけ保存される）。
- **FR-COVER-04 [MUST]** サムネイル（長辺 80px・160px・320px。一覧は 80px、詳細とフォームは 320px）は端末ごとに生成して、ローカルにキャッシュする（同期はしない）。一覧の書影は、WebView のメモリを抑えるため、画像のキャッシュをさせない（`docs/decisions/0010`）。
- **FR-COVER-05 [MUST]** 書影を手動で差し替えられる（ファイルのドラッグ＆ドロップ、クリップボードからの貼り付け、画像 URL の入力、取得元の候補から選ぶ）。
- **FR-COVER-06 [COULD]** 書影の回転と切り抜き。
- Amazon 由来の書影を保存するかどうかは、規約を確認してから決める（13章）。

### 7.5 一覧・検索・分類（FR-LIST）

- **FR-LIST-01 [MUST]** メイン画面は表形式の一覧。列の表示・非表示、並べ替え、幅の変更ができ、設定は端末ごとに保存する。
  - 既定の列: 書影（小）、書名、巻次、著者、出版社、発行日、内容（Cコード）、保管場所、読書状況、評価、登録日
  - 選べる列: ISBN、シリーズ、本体価格、購入日、購入価格、購入店、NDC、発行形態、販売対象、ページ数、タグ、所有状態、読了日
- **FR-LIST-02 [MUST]** 複数の列を組み合わせて並べ替えられる。日本語の書名は、ヨミがあればヨミ順で並べる。
- **FR-LIST-03 [MUST]** 検索欄で、書名・ヨミ・著者・出版社・シリーズ・タグ・メモ・ISBN をまとめて検索する。入力しながら結果が絞り込まれる。
  - ひらがなとカタカナ、全角と半角、英字の大文字と小文字は区別しない。
  - ISBN はハイフンありでも、ISBN-10 でも検索できる。
  - 実装は FTS5 の trigram トークナイザを使い、2 文字以下の検索語は LIKE 検索に切り替える。
- **FR-LIST-04 [MUST]** 左のサイドバーで絞り込む。
  - ライブラリ: すべて／所有／欲しい本／手放した／ゴミ箱
  - 読書状況: 未読／読書中／読了／中断
  - 保管場所（ツリー）
  - タグ（ツリー）
  - 自動分類: 内容（Cコードの大分類 → 中分類）、発行形態、出版社、著者、発行年、取得待ち・情報不足の本
- **FR-LIST-05 [SHOULD]** 検索条件に名前を付けて「スマート本棚」として保存できる（例:「読了・★4以上・2026年」）。
- **FR-LIST-06 [MUST]** 一覧の右側に、選んだ本の詳細ペイン（大きい書影と全項目）を表示する。表示・非表示を切り替えられる。
- **FR-LIST-07 [COULD]** 書影を並べたグリッド表示に切り替えられる。

### 7.6 読書記録・購入情報・欲しい本（FR-READ／FR-BUY／FR-WISH）

- **FR-READ-01 [MUST]** 読書状況（未読／読書中／読了／中断）、読み始めた日、読了日、評価（★1〜5）、感想（複数行テキスト）を記録できる。
- **FR-READ-02 [MUST]** 読書状況を「読了」にしたとき、読了日が空なら今日の日付を入れる。
- **FR-READ-03 [COULD]** 再読の履歴（読んだ期間を複数）を記録できる。
- **FR-BUY-01 [MUST]** 購入日、購入店、実際に払った金額（税込）、購入メモを記録できる。購入店は過去の入力から候補を出す。
- **FR-BUY-02 [SHOULD]** 新品・中古の区別を記録できる。
- **FR-WISH-01 [MUST]** 「欲しい本」は通常の書籍と同じ項目を持ち、所有状態だけが異なる。欲しい本の一覧から、購入済みにする操作ができる。
- **FR-WISH-02 [SHOULD]** 欲しい本に優先度（高・中・低）とメモを付けられる。

### 7.7 集計（FR-STAT）[SHOULD]

- 所有冊数（所有状態別、読書状況別）
- 内容（Cコード大分類）別、発行形態別、出版社別（上位 N 件）の冊数
- 年別・月別の登録冊数、読了冊数
- 年別・月別の購入金額、本体価格の合計
- 表とシンプルなグラフで表示し、CSV に書き出せる

### 7.8 同期（FR-SYNC）

設計の詳細は「8.3 同期フォルダの構成と変更ログ」を参照。

- **FR-SYNC-01 [MUST]** 設定画面で同期フォルダを選ぶと同期が始まる。同期フォルダを設定しなくても、単体で全機能が使える。
- **FR-SYNC-02 [MUST]** アプリは Google Drive などの API を直接呼ばず、ローカルのフォルダとして読み書きするだけにする。同期はクラウドサービスのクライアントに任せる。
- **FR-SYNC-03 [MUST]** SQLite データベースは端末ローカル（アプリのデータフォルダ）に置き、同期フォルダには変更ログと書影だけを置く。データフォルダは、macOS では `~/Library/Application Support/<バンドル ID>/`、Windows では `%LOCALAPPDATA%\<バンドル ID>\` とする（Windows の Roaming（`%APPDATA%`）は、プロファイルと一緒に他の PC へ移動しうるため使わない）。
- **FR-SYNC-04 [MUST]** 各端末は、同期フォルダ内の自分専用のサブフォルダにだけ書き込む。他の端末のファイルは読むだけにする（同じファイルを 2 台が書き換える状況を作らない）。例外は書影のフォルダ（`covers/`）で、全端末が書く。ファイル名が内容の SHA-256 なので、同じ名前なら内容も同じで、上書きしても壊れない（既にあれば書かない）。
- **FR-SYNC-05 [MUST]** 複数の端末を同時に起動しても、オフラインで編集しても、最終的に全端末が同じ状態になる。衝突は項目単位の Last-Writer-Wins（ハイブリッド論理時計の新しい方が勝つ）で解決する。別々の端末で同じ本の別の項目を変えた場合は、両方の変更が残る。
- **FR-SYNC-06 [MUST]** 他の端末の変更は、起動時、ウィンドウが前面に来たとき、ファイル監視の通知、60 秒ごとのポーリングで取り込む。
- **FR-SYNC-07 [MUST]** 自分の変更は、最後の変更から 5 秒後（まとめ書き。ただし変更が続いても、最初の変更から 30 秒以内には書き出す）と終了時に書き出す。
- **FR-SYNC-08 [MUST]** 画面に同期状態を表示する（最終書き出し時刻、最終取り込み時刻、未書き出しの件数、エラー）。
- **FR-SYNC-09 [MUST]** 初めて同期フォルダを設定するときは、次のどちらかを選ぶ。
  - 新しいライブラリを作る（手元のデータを書き出す）
  - 既存のライブラリに参加する（手元が空なら取り込むだけ。手元にデータがあれば、統合するか置き換えるかを選ぶ）
- **FR-SYNC-10 [MUST]** 別のライブラリのフォルダを誤って指定した場合は、ライブラリ ID の不一致を検出して警告する。
- **FR-SYNC-11 [MUST]** 端末の時計が大きくずれている（他端末の時刻が 5 分以上未来）場合は警告する。
- **FR-SYNC-12 [SHOULD]** 同期フォルダの場所はトランスポート層（`SyncTransport` トレイト）で抽象化する。初版はローカルフォルダ実装のみ。将来、モバイル版向けに Google Drive API 実装などを追加できるようにする。
- **FR-SYNC-13 [SHOULD]** 書影の参照が残っていない画像を、手動操作で削除できる（ファイルの更新時刻が 30 日以上前のものに限る）。

### 7.9 入出力とバックアップ（FR-IO）

- **FR-IO-01 [MUST]** CSV（UTF-8、BOM 付きで Excel でも文字化けしない）で全項目を書き出せる。表示中の絞り込み結果だけを書き出すこともできる。
- **FR-IO-02 [MUST]** JSON で全データ（ID、項目ごとの時計情報を含む）を書き出せる。
- **FR-IO-03 [MUST]** ISBN の一覧（テキストファイル。1 行に 1 つ、2段目のコードが混ざっていてもよい）から一括登録できる。処理は連続登録モードと同じ流れにする。
- **FR-IO-04 [SHOULD]** 汎用 CSV から取り込める。列と項目の対応は画面で指定する。
- **FR-IO-05 [MUST]** ローカルの DB を毎日自動でバックアップする（SQLite の `VACUUM INTO` を使い、日次 7 世代と週次 4 世代を残す）。手動バックアップと復元もできる。
- **FR-IO-06 [COULD]** 書影も含めた ZIP 形式で書き出せる。

### 7.10 設定（FR-CONF）

- **FR-CONF-01 [MUST]** 同期: 同期フォルダ、端末名、同期状態の詳細
- **FR-CONF-02 [MUST]** 取得元: 有効・無効、項目ごとの優先順位（和書・洋書などの 2 組）、API キー（OS のキーチェーンに保存し、同期しない）、接続テストボタン
- **FR-CONF-03 [MUST]** スキャン: 末尾キー、ペアリングのタイムアウト、キー間隔の閾値、音の種類と音量
- **FR-CONF-04 [MUST]** 表示: テーマ（OS に連動／ライト／ダーク）、フォント（既定は OS の日本語フォント）、文字サイズ、一覧の列
  - 既定の配色: ライトは Catppuccin Latte、ダークは Catppuccin Mocha
- **FR-CONF-05 [MUST]** 価格表示: 本体価格（税抜）を基本とし、税込価格を併記するか選べる（税率は既定 10%）。
- **FR-CONF-06 [MUST]** バックアップ: 保存先、世代数
- **FR-CONF-07 [MUST]** 「このアプリについて」に、各取得元のクレジット表記を表示する。

## 8. データ設計

### 8.1 エンティティ

| エンティティ | 同期 | 内容 |
|---|---|---|
| book（書籍） | する | 書誌、所有状態、保管場所、タグ、読書記録、購入情報、メモ、取得元の記録 |
| series（シリーズ） | する | シリーズ名、ヨミ、メモ |
| location（保管場所） | する | 名前、親、並び順（ツリー） |
| tag（タグの属性） | する | タグ名、色。どの本に付くかは book の `tags` 項目が持つ |
| shelf（スマート本棚） | する | 名前、検索条件（JSON）、並び順 |
| 設定 | しない | 列の配置、ウィンドウ、取得元の設定、スキャン設定など。端末ごとに持つ |
| API キー | しない | OS のキーチェーンに端末ごとに保存 |
| 取得元キャッシュ、サムネイル | しない | 端末ごとに作り直せる |

- ID はすべて UUIDv7。
- 同期の単位は「エンティティ＋ID＋項目」。配列の項目（著者、タグ）は配列全体を 1 つの値として扱う。
- 書籍の取得元の記録と手修正の記録は、項目ごとに別の同期キー（`field_sources.<項目名>`、`manual_fields.<項目名>`）として扱う。1 つの値にまとめると、別々の端末で別の項目を手で直したときに、片方の記録が LWW で消えるため（`docs/decisions/0005`）。
- 削除は `deleted` 項目の変更として扱う（削除の記録＝トゥームストーン）。ほかの項目を編集しても削除は取り消されない。復元は `deleted=false` を新しい時刻で書き込む。

### 8.2 SQLite スキーマ案

叩き台であり、実装で調整してよい。ただし「項目単位で時計を持つ」「変更は outbox に記録する」の 2 点は守る。実際のスキーマは `crates/core/migrations/` を正とする。

次の点は実装時に決めた（`docs/decisions/0003`、`0004`、`0005`）。下の SQL にも反映してある。

- 同期対象テーブルの `id` 以外の NOT NULL 列には、すべて既定値を付ける。他端末の Op は順不同・欠番ありで届くので、作成 Op より先に部分的な更新が届いても、`id` だけで行を作れるようにするため。
- 未知の項目を保持する `extra_json` は、books 以外の同期対象テーブルにも付ける。
- `tags.name` は UNIQUE にしない。2 台が同じ名前のタグを別の ID で作ると、取り込み時に制約違反で適用できなくなるため。同じ名前が複数あるときは、ID が最小（最古）のものを使う。
- `field_sources_json` と `manual_fields_json` は保存形式で、Op では項目ごとのキー（8.1）で同期する。
- `updated_at` は端末ローカルの派生値で、同期しない。
- 同期対象テーブル間に外部キー制約は作らない（参照先がまだ届いていないことがあるため）。
- 検索と並べ替えのための派生データ（`books_fts`、`book_tags` など）は端末ローカルに持ち、Op を適用したときに更新する。

### 8.3 同期フォルダの構成と変更ログ

#### フォルダ構成

```
<同期フォルダ>/bibcontainer-library/
├─ library.json                      … ライブラリ ID、形式バージョン、読める最低のアプリ版
├─ devices/<device_id>.json          … 端末名、OS、アプリ版、最終書き出し時刻（その端末だけが書く）
├─ ops/<device_id>/
│   ├─ 0000000001-0000000250.jsonl   … 変更ログのセグメント（書き込み後は変更しない）
│   └─ 0000000251-0000000260.jsonl
├─ covers/ab/ab12…ef.jpg             … 書影（SHA-256 のファイル名。変更しない。全端末が書く。FR-SYNC-04 の例外）
└─ snapshots/<device_id>/<ミリ秒15桁>-<カウンタ5桁>.jsonl.gz … 全状態のスナップショット（HLC の `:` は Windows のファイル名に使えないので使わない）
```

#### 変更ログ（Op）の形式

1 行 1 Op の JSON Lines。

```json
{"v":1,"dev":"d-7f3a2c","seq":251,"hlc":"001760412345678:00000:d-7f3a2c","ent":"book","id":"0192f3a0-6c1e-7cc3-9b1a-2f4e8d1c0a55","set":{"title":"坊っちゃん","rating":4}}
{"v":1,"dev":"d-7f3a2c","seq":252,"hlc":"001760412345901:00000:d-7f3a2c","ent":"book","id":"0192f3a0-6c1e-7cc3-9b1a-2f4e8d1c0a55","set":{"deleted":true}}
{"end":true,"count":2,"sha256":"<上の行すべての SHA-256>"}
```

- `v`: 形式のバージョン。`dev`: 端末 ID。`seq`: 端末内の通し番号。`hlc`: ハイブリッド論理時計。`ent`／`id`: 対象。`set`: 変更した項目と新しい値。書籍の取得元と手修正の記録は、`"field_sources.title":"openbd"`、`"manual_fields.title":true` のように項目ごとのキーで書く（null で消す）。
- 新規作成は、全項目を `set` に入れた Op として書く。
- 最終行は終端レコード。件数とハッシュが合わないファイルは書き込み途中か同期途中とみなし、読まずに後で再試行する。

#### 書き出しと取り込みのルール

- **HLC の形式**: `{ミリ秒（15桁ゼロ埋め）}:{カウンタ（5桁）}:{device_id}`。文字列として比較すれば時刻順になり、端末 ID を含むので同じ値は生じない。
  - 自分の変更時: `ms = max(現在時刻, 前回の ms)`。ms が前回と同じならカウンタを 1 増やし、違えば 0 に戻す。
  - 他端末の Op を取り込むとき: 自分の時計を `max(自分, 受け取った HLC)` に進める。
- **変更の記録**: DB の更新と outbox への追記は、同じトランザクションで行う。
- **書き出し**: outbox の未書き出し分から 1 つのセグメントを作る。同じフォルダに `.tmp-<乱数>` という名前で書いてからリネームし、成功したら `flushed=1` にする。
- **読み込み対象**: ファイル名が `^\d{10}-\d{10}\.jsonl$` に一致するものだけを読む。一致しないもの（`… (1).jsonl` のような同期サービスの衝突コピーなど）は読まず、ログに警告を出す。
- **適用**: Op の項目ごとに、`field_clocks` の HLC より新しければ値と時計を更新する。この処理は何度繰り返しても、どの順番で行っても結果が同じになる。そのため、seq に欠番があっても届いたセグメントから適用してよい。
- **未知の項目**: 新しい版の端末から届いた知らない項目は `extra_json` に保持する。`library.json` の「読める最低のアプリ版」より古いアプリは、読み取り専用で動かし、更新を促す。
- **書影**: 書影ファイルを書いてから、それを参照する Op を書く。参照先のファイルがまだ届いていなければ仮の表紙を表示し、後で再確認する。
- **自分のセグメントの統合** [SHOULD]: 30 日より古い自分のセグメントを 1 つにまとめ、元のファイルを消してよい（自分のフォルダは自分しか書かないので安全）。読む側は、取り込み済みの範囲で全部覆われているファイルは読まないので、重複して適用されない。
- **スナップショット**: 全エンティティの値と項目ごとの HLC、含まれる Op の範囲（端末ごとに、seq 1 から切れ目なく適用した最大値）を書く。各端末の最新のスナップショットを、まだ読んでいなければ一度ずつ適用し、その後のセグメントを取り込む（項目ごとの LWW なので、重ねて適用しても結果は変わらない。復元した DB や統合で加わった端末の状態も、これで他の端末に届く）。新しいライブラリの作成、統合、バックアップからの復元のあとと、自分の Op が一定数たまったときに書く。詳細は `docs/decisions/0013`・`0014`。

#### Google Drive を使う際の注意

- ストリーミングモードでは、ファイルが必要になるまでダウンロードされない。ライブラリのフォルダを「オフラインで使用可能」に設定するか、ミラーリングモードを使うことを推奨する（アプリ内のヘルプに書く）。
- 仮想ドライブ（Windows の `G:`）では、ファイル監視の通知が届かないことがある。そのため定期ポーリングを必ず併用する。
- 書き出した変更が他の端末に届くまでには、Google Drive のアップロードとダウンロードの時間（数秒〜数分）がかかる。
- 容量の目安: 5,000 冊で変更ログは数 MB、書影は 250〜500MB 程度。

## 10. 非機能要件

### 10.1 性能（5,000 冊、SSD の環境で）

| 項目 | 目標 |
|---|---|
| 起動から一覧表示まで | 2 秒以内 |
| 検索の応答 | 100ms 以内（2 万冊でも 300ms 以内） |
| 一覧のスクロール | 引っかかりなく動く（60fps 目安） |
| スキャンから 2段目のデコード結果表示まで | 100ms 以内 |
| 書誌取得 | 通常 5 秒以内（ネットワーク次第） |
| メモリ使用量 | 300MB 以下 |

### 10.2 信頼性

- SQLite は WAL モード。すべての更新をトランザクションで行い、強制終了してもデータが壊れないこと。
- DB のスキーマ変更はマイグレーションで行い、適用前に自動でバックアップを取る。
- 同期フォルダが使えない（未接続、容量不足、権限エラー）ときも、ローカルでの操作は止めない。

### 10.3 セキュリティとプライバシー

- 利用状況の送信（テレメトリ）はしない。
- 通信先は、有効にした取得元と、ユーザーが入力した画像 URL だけ。
- API キーは OS のキーチェーンに保存する。ソースコード、設定ファイル、ログ、同期フォルダには書かない。ログに出す URL からはキーを伏せる。

### 10.4 移植性

- macOS（arm64）と Windows（x64）で同じ機能を提供する。
- パスの扱い（区切り文字、日本語を含むパス、長いパス）は両 OS で確認する。
- 改行コードとファイル名の Unicode 正規化（macOS は NFD になる場合がある）の違いに注意する。

### 10.5 保守性

- Rust: rustfmt と clippy（警告ゼロ）。フロント: ESLint と Prettier。
- バーコード処理、HLC、Op の適用、取得元ごとのマッピングには単体テストを書く。取得元のマッピングは、保存した応答（フィクスチャ）を使ってテストする。
- 同期エンジンには、3 台の端末を模擬し、ランダムな操作をランダムな順で適用しても全端末が同じ状態に収束することを確かめる性質テストを書く（proptest など）。

### 10.6 外部サービスの規約とクレジット

- 各取得元の利用条件とクレジット表記に従い、「このアプリについて」に表示する（NDLサーチ、openBD、Google Books、Open Library、楽天ウェブサービス、Amazon）。
- Open Library は、「このアプリについて」に Open Library へのリンクを置く（書影 API の作法による依頼）。
- アプリを公開する場合は、利用者が自分で各 API の登録・キー入力をする前提にする（作者のキーを同梱しない）。

### 10.7 配布

- 自分用の段階では、署名なしのビルドでよい（macOS では初回起動時に右クリックから開く）。
- 公開する場合は、macOS の公証（Apple Developer Program への登録が必要）、Windows の署名、自動更新（tauri-plugin-updater）を検討する（13章）。

## 11. 外部 API メモ（2026年10月時点の調査結果。実装前に公式情報で確認すること）

### 11.1 openBD

- 書誌: `GET https://api.openbd.jp/v1/get?isbn=9784780802047,9784003101117`
  - ISBN ごとの配列が返る。未収録の ISBN は `null`。
- 主な項目:
  - `summary.title` / `volume` / `series` / `publisher` / `pubdate` / `author` / `cover`
  - Cコード: `onix.DescriptiveDetail.Subject[]` のうち `SubjectSchemeIdentifier` が `"78"` のものの `SubjectCode`（`"79"` はジャンルコード）
  - 価格: `onix.ProductSupply.SupplyDetail.Price[].PriceAmount`（`PriceType` が `"01"` なら税抜）
  - 内容紹介: `onix.CollateralDetail.TextContent[]`（`TextType` が `"03"` は内容紹介、`"02"` は短い説明、`"04"` は目次）
  - 書影: `summary.cover`（例: `https://cover.openbd.jp/9784780802047.jpg`）
- 確認結果: 9784780802047 で、書名「おにぎりレシピ101」、出版社「ポット出版」、Cコード `0077`、価格 1300 円、書影 URL が返った。
- 状況: 2023年7月に「v1 の提供終了」が告知されたが、2026年10月時点でも応答がある。いつ止まってもよいように、ほかの取得元だけでも動く作りにする。
- 中身は 2 種類ある（2026-10 確認）。版元ドットコム会員社の本は上記の項目がそろう。それ以外は NDL の書誌の簡易な変換で、Cコード・内容紹介・書影・ページ数がなく、著者が `夏目,漱石,1867-1916`、価格が `310 (税込)` のような形になり、書名に巻次や副書名が混ざることがある。詳細は `docs/decisions/0007`。
- 規約: 本の紹介・宣伝のために利用できる。データの改変はしない、削除依頼に応じる、などの条件がある（https://openbd.jp/terms/）。

### 11.2 NDLサーチ

- 書誌（SRU）: `GET https://ndlsearch.ndl.go.jp/api/sru?operation=searchRetrieve&recordSchema=dcndl&maximumRecords=5&query=isbn%3D9784003101117`
  - 応答は XML（DC-NDL 形式）。同じ ISBN で複数のレコードが返ることがあるので、図書のレコードを選ぶ。
  - 使う要素（実装時に実際の応答で確認）: 書名、書名のヨミ（`dcndl:transcription`）、著者、出版社、出版年、価格（`dcndl:price`）、数量（`dcterms:extent`。例: `218p ; 15cm`）、NDC（`dcterms:subject` の NDC9／NDC10）、シリーズ（`dcndl:seriesTitle`）、巻次（`dcndl:volume`）
  - 実際の応答で確認した点（2026-10）: `recordPacking=xml` と `onlyBib=true` を付ける。書名・巻次・シリーズは `rdf:Description/rdf:value` の入れ子、NDC は `dcterms:subject` の `rdf:resource` の URL に入る。シリーズ全体を 1 件にまとめたレコードや、誤登録の ISBN（型が `ErrorISBN`）のレコードも返るので、型が `ISBN` の識別子で一致するものだけを使う。該当なしは HTTP 200 で `Record does not exist`。詳細は `docs/decisions/0007`。
- 書影: `https://ndlsearch.ndl.go.jp/thumbnail/{ISBN13}.jpg` は使わない（公式の仕様書に記載がなく、NDL サーチ以外からの参照は 403 になる。FR-META-02 の注記）。
- 利用条件:
  - 個人や非営利団体で収益がなければ、利用申請は不要。
  - 継続的にアクセスする場合は、申請フォームで連絡先と用途を伝えるよう求められている（13章）。
  - 並列リクエストの大量送信はしない。同時接続数に上限があり、短時間の大量アクセスは遮断される。
  - API を使うサイトやアプリでは、NDLサーチの API を使っていることを表示する。

### 11.3 Google Books

- `GET https://www.googleapis.com/books/v1/volumes?q=isbn:9784003101117&key=…`
- API キーが必要。キーなしでは常に 429（`Queries per day`、割り当て 0）になる（2026-10 確認）。キーは Google Cloud Console で Books API を有効にして作り、アプリの設定画面で入力する。
- 使う項目: `items[0].volumeInfo` の `title` / `subtitle` / `authors[]` / `publisher` / `publishedDate` / `description` / `pageCount` / `imageLinks.thumbnail` / `language`
- 書影 URL が `http://` の場合は `https://` に置き換える。`edge=curl` を外し、`zoom=0` にすると大きい画像が取れる。
- `q=isbn:` が 0 件のときは、Dynamic Links（`https://books.google.com/books?bibkeys=ISBN:<ISBN>&jscmd=viewapi`、キー不要）で volume ID を得て、`volumes/<ID>` を取る（2026-10 の障害への回避策。`docs/decisions/0018`）。volume の `industryIdentifiers` の ISBN が合うものだけを使う。書影は `books/content?id=<ID>&printsec=frontcover&img=1&zoom=0`（ダミーなら `zoom=1`）。
- 和書は収録が不揃いで、出版社が空のことが多い。和書では補完用として使う（洋書などでは優先する。FR-META-04）。

### 11.4 Open Library

- キー不要。主に洋書で、和書はほとんど収録がない。詳細は `docs/decisions/0017`。
- 書誌は 2 回の通信で取る。
  1. 検索: `GET https://openlibrary.org/search.json?isbn=<ISBN-13>&fields=key,title,author_name,editions,editions.key,editions.title,editions.subtitle,editions.author_name,editions.publisher,editions.publish_date,editions.language,editions.cover_i,editions.isbn`。`docs` が空なら該当なし（ここで終わる）。`editions.docs` から ISBN の合う版を選ぶ。著者名は検索の版の `author_name` から取る。
  2. 版の JSON: `GET https://openlibrary.org/books/<OLID>.json`。ページ数（`number_of_pages`）と内容紹介（`description`。文字列か `{type, value}`）のため。404 と統合された版（`/type/redirect`）は、検索の値だけで続ける。
- `/isbn/<ISBN>.json`（版の JSON への転送）は、著者が参照（`/authors/…`）だけで名前がなく、作品・著者の JSON が別に要るので使わない。`/api/books` は legacy で、いずれ廃止されうる。
- 書影: 版の `covers`（`-1` は削除済み）の最初の正の ID から `https://covers.openlibrary.org/b/id/<ID>-L.jpg?default=false`（書影がなければ 404）。ISBN を指定した書影の URL は、IP ごとに 5 分で 100 回までの制限があるので使わない（書影 ID での取得は制限されない）。
- 発行日は英語の自由な書式（`July 2008`、`Mar 05, 2016`、`c1995` など）。
- 利用の作法: 名乗らないリクエストは 1 秒に 1 回（User-Agent にメールか電話番号を入れると 3 回だが、利用者の個人情報を出さないため使わない）。API での大量取得・書影 API のクロールはしない。書影 API は公開のウェブサイトでの表示のためのもので、大量ダウンロード用ではない。Open Library へのリンクを「このアプリについて」などに置くよう依頼されている。

### 11.5 楽天ブックス書籍検索 API（任意）

- 2026年5月に新仕様へ移行した。エンドポイントは `openapi.rakuten.co.jp` 系に変わり、アプリケーション ID に加えてアクセスキーが必要になった。旧エンドポイント（`app.rakuten.co.jp`）は 2026-05-13 で停止。
- 登録したアプリの許可サイトと Referer が合わないとエラーになる、という報告がある。デスクトップアプリからの呼び出しでどう扱われるか、実装時に確認する（13章）。
- パラメータ: `isbn`、`formatVersion=2` など
- 使う項目: `title`、`titleKana`、`subTitle`、`seriesName`、`author`、`authorKana`、`publisherName`、`size`、`isbn`、`itemCaption`、`salesDate`、`itemPrice`（税込）、`largeImageUrl`
- クレジット表記が必要。

### 11.6 Amazon Creators API（任意）

- 利用資格: Amazon アソシエイトで最終承認済みであり、かつ直近 30 日間に 10 件以上の紹介販売があること。登録できるのはアカウントの主所有者だけ。
- 旧 PA-API v5 は 2026年5月に停止した。
- 認証: OAuth 2.0 のクライアントクレデンシャル方式。発行された Credential ID・Secret・Version を使ってアクセストークンを取得する。認証情報のバージョンによって、トークンの取得先とスコープが異なる。
- エンドポイント: `https://creatorsapi.amazon/catalog/v1/`。マーケットプレイスは `x-marketplace` ヘッダーで指定する（日本は `www.amazon.co.jp`）。GetItems は 1 回 10 件まで。
- 書籍の ASIN は、`978` で始まる ISBN なら多くの場合 ISBN-10 と同じ。`979` の場合はキーワード検索で探す。
- 認証方式やエンドポイントの一部は第三者の記事に基づく。実装時は必ず公式ドキュメントで確認する。
- 規約上、取得データの保存期間や書影の扱いに制約がある可能性が高い（13章）。
