## 背景

0022 §1 の 6 番目（FR-IO-04 [SHOULD]）。0022 で決まっていたこと: 文字コードは UTF-8（BOM の有無とも）と Shift_JIS を自動で判定する。列と項目の対応は画面で選ぶ。ISBN のある行は書誌も取り、CSV の値を優先する（由来は `import`）。登録済みの ISBN は飛ばす。アプリ自身の CSV の書き出し（FR-IO-01、0006 §9）を取り込み直せることも確かめる。著者・タグ・保管場所・シリーズなど、文字列から解決が要る項目の扱い、ISBN のない行、エラーのある行の見せ方は、このセッションで決めた。

2 章のとおり、私本管理からの移行はしない。取り込みは汎用の CSV で、他のアプリ固有の値の言い換え（「読みたい」→ 読書状況など）は作らない。

一括再取得（0027）のセッションと並行した。受け入れ基準の番号は、0027 に AT-46〜AT-49 を、この記録に AT-50 以降を割り当てた。

## 決定

### 1. 流れ

- 入口: 設定の「バックアップ」の節で、「書き出し」の隣に「取り込み」を置き、「CSV から取り込む…」でファイルを選ぶ。ブラウザのモック（`pnpm dev`）では、「バックアップ」の節がアプリでのみ使える旨だけを出す（書き出しと同じ）ので、取り込みのボタンも出ない。
- ダイアログの段階: 1. 列の対応 → 2. 確認（件数と、問題のある行の一覧）→ 3. 取り込み → 4. 結果。**確認の画面までは DB を変えない。**
- コマンドはどれもファイルのパスを受け取り、そのつど読み直す（20 MB まで）。`csv_import_open`（列・例・対応の案）、`csv_import_check`（行の分類）、`csv_import_run`（取り込み）、`csv_import_save_rejected`（取り込めなかった行の保存）。

### 2. 読み込み（`crates/core/src/csv_import/`）

- 文字コード: BOM（`EF BB BF`）があれば UTF-8。なければ、UTF-8 として厳密に読めれば UTF-8、読めなければ Shift_JIS（`encoding_rs::SHIFT_JIS`。WHATWG の Shift_JIS で、Windows-31J の ①・髙 なども読める）。Shift_JIS でも読めなければ、エラー（「文字コードを判定できませんでした」）。画面で UTF-8・Shift_JIS を選び直せる（選んだときは、読めない文字を置き換えて続ける）。
- CSV: `,` 区切り、RFC 4180 の `"` の囲み・`""`・欄の中の改行（`csv` クレート）。行ごとに列の数が違ってよい（足りない欄は空、余った欄は使わない）。全部が空の行は数えない。行番号は、レコードが始まる物理的な行（見出しが 1 行目）。CRLF と LF で同じになるよう、バイトの位置から数える。
- 書き出しが数式よけに付けた `'`（`'` の次が `=`・`+`・`-`・`@`・タブ・CR）は外す。前後の空白は除く。
- 「1 行目は見出し」（既定はオン）。外すと、1 行目もデータで、列の名前は「N 列目」。

### 3. 列と項目の対応

- 列ごとに、先頭 3 行の値を例として見せ、項目を選ぶ（`<select>` の `<optgroup>` で、書誌・分類・保管・読書・購入・その他に分ける）。文字コードや「1 行目は見出し」を変えると、開き直して、対応も案に戻す。1 つの項目には 1 列だけ（選ぶと、前にその項目だった列は「取り込まない」に戻る）。ISBN か書名の列がないと先へ進めない。
- 選べる項目（`ImportTarget`）: 書籍の項目のうち、書影と取得状態を除く全部（シリーズ・保管場所は名前・パスで）、`ID`（登録済みかの確認だけに使い、書かない）、`ゴミ箱`（「はい」の行を飛ばす）、`登録日時`。
- 見出しから自動で選ぶ（NFKC・前後の空白・大文字小文字を無視）: 書き出しの列名の全部（`書影`・`取得状態` は選ばない）と、少しの別名（`ISBN13`・`タイトル`・`書籍名`・`title`・`著者名`・`作者`・`author`・`出版日`・`発売日`・`レビュー`・`価格`・`定価` など）。同じ項目になる見出しが 2 つあれば、前の列。

### 4. 値の読み方

読めない値は、**その項目だけ空にして、行は取り込む**（警告）。読めたあとにコアの検証（`canonical_book_value`）でも確かめるので、取り込みの途中で検証のエラーにならない。

| 項目 | 読み方 |
|---|---|
| ISBN | ISBN-13・ISBN-10、ハイフン・全角も可（`barcode::classify`。ISBN-13 にそろえる）。空なら ISBN なし。読めなければ**その行はエラー**。`9.78478E+12` の形は「Excel で数値になり桁が落ちた可能性」と出す |
| 著者 | `;`・`；`・`、`・改行で区切る。末尾の `（…）`・`(…)` は役割。`,` では区切らない（`Smith, John`・NDL の `夏目, 漱石` のため） |
| タグ | `;`・`；`・`,`・`，`・`、`・改行で区切る（スキャン登録の共通値と同じ区切りに、書き出しの `; ` を足したもの） |
| 保管場所 | NFKC にして `>` で区切ったパス。(1) 根からのパスが合う場所（各段を `normalize_for_search` で比べる）。(2) 区切りのない名前で、根に同じ名前がなければ、同じ名前の場所が全体で 1 つだけならそれ。(3) それ以外は、合うところまでたどり、足りない段を親から順に作る |
| シリーズ | 正規化した名前で探し、なければ作る（手動登録と同じ `find_or_create_series_in`） |
| 所有状態・優先度・読書状況・新品中古 | 書き出しの日本語名（`所有`・`欲しい本`・`手放した`、`高`・`中`・`低`、`未読`・`読書中`・`読了`・`中断`、`新品`・`中古`）と英語のキー |
| 日付 | `YYYY`・`YYYY-M`・`YYYY-M-D`（`-`・`/`・`.`）と `YYYY年M月D日` など。時刻は捨てる |
| 金額・ページ数 | `円`・`¥`・`,`・空白、末尾の `p`・`ページ`・`頁` を外した 0 以上の整数（`1200.0` も可） |
| 評価 | 1〜5。`0` は警告なしで空（未評価として使うアプリがあるため） |
| 作品（手動） | `まとめない`・`none` と作品の ID |
| ゴミ箱 | `はい`・`true`・`1`・`yes`・`○` などは、その行を飛ばす。`いいえ`・`false`・`0`・空は飛ばさない |
| 登録日時 | ISO 8601（`Z`・時差つき）は UTC に、時差のない `YYYY-MM-DD[ HH:MM[:SS]]` はローカル時刻として、書き出しと同じ `YYYY-MM-DDTHH:MM:SS.mmmZ` にする |
| ほかの文字の項目 | 前後の空白を除き、空なら入れない |

### 5. 行の分類（この順に決める）

| 分類 | 条件 |
|---|---|
| エラー（取り込まない） | ISBN が読めない／書名も ISBN もない |
| 飛ばす | ゴミ箱の列が「はい」／`ID` の列と同じ ID の本がある（ゴミ箱の本も。完全削除した本は除く）／ISBN が登録済み（ゴミ箱と完全削除の本を除く全部。所有・欲しい本・手放した本のどれでも）／この CSV のもっと前の行（取り込む行）と ISBN か ID が同じ |
| 取り込む | それ以外（読めない値があれば警告つき） |

- 確認の画面に、件数（取り込む・そのうち書誌を取りに行く・飛ばすの理由ごと・エラー・警告）、新しく作る保管場所（パス）とシリーズ、問題のある行の一覧（行番号・ISBN か書名・理由。登録済みなら登録済みの本の書名）を出す。
- ISBN があって書名のない行は取り込む（書名はあとの取得で入る）。
- **手放した本の ISBN も飛ばす**: スキャンでは、手放した本だけの ISBN は買い直しとして新しい本にする（0012 §4）が、取り込みは買い直しではない。飛ばさないと、書き出しを取り込み直したときに本が重なる。

### 6. 取り込み

- 1 つのトランザクションで、分類をやり直してから（確認のあとで変わった蔵書に合わせる）、保管場所（親から順。新しい `create_location_in`）、シリーズ、本を作る。どれも `record_change` で Op になり、同期で他の端末に届く。1 件でも失敗したら、全部を取り消す。
- 値の由来は `import`（`FieldChange::import`）。巻次から作る並べ替え用の数値も `import`。
- **ISBN のある本は取得待ち（`meta_status = pending`）で作り**、取り込みのあとすぐ、取得待ちの自動の再取得（0010 §9）を動かす（`trigger_now`。前面に来たときの `trigger` の 30 秒の間隔を無視する。すでに走っていれば、次の 5 分ごとの回に回る）。CSV にない項目と書影が、取得元の値で埋まる。ISBN のない本は取得しない（取得状態は付けない）。
- 登録日時の列があれば、その時刻で作る（新しい `create_book_with_created_at_in`。Op の `set` の `created_at` がその値になる）。なければ今の時刻。
- 成功したら `library-changed`（新しい本の ID、`others = true`）。
- 結果の画面に件数と、「取得待ち」の本の書誌・書影は裏で順に取得すること（サイドバーの「取得待ち」で残りが分かる）を出す。エラーの行があれば「取り込めなかった行を CSV に保存…」: 元の見出しと値のまま、末尾に「取り込めなかった理由」の列を足し、書き出しと同じ形（UTF-8 の BOM、CRLF、数式よけ）で書く。直して取り込み直しても、取り込んだ行は入っていないので重ならない。

### 7. 取り込んだ値を再取得で置き換えない（`src-tauri/src/metadata/refetch.rs`）

- 再取得（自動の取得待ち・手動・一括）の `plan` で、`field_sources.<項目>` が `import` の項目を、手修正の項目と同じく守る（`protected = (手修正 または import) かつ 上書きしない`）。組になる項目も手修正と同じ扱い（巻次を守れば並べ替え用の数値も書かない、シリーズを守ればシリーズを探さない・作らない、Cコード・本体価格）。取得元が値を返さなくなった項目を消す処理（0021 §3）は、もともと取得元の由来の項目にしか効かない。
- 「手で直した項目も上書きする」（`overrideManual`）のときだけ置き換える。チェックの文言を「手で直した項目・取り込んだ項目も上書きする」に変えた。
- コアの規則（0006 §2: `Import` は `Provider` と同じく、手修正の項目だけを守る）は変えていない。取得元の値を既存の本に書くのは再取得だけなので、再取得の側で守れば足りる。

## 理由

- **取り込みのときに書誌を取らず、取得待ちの自動の再取得に任せる**: 数百冊の取り込みで、取得元のレート制限のぶん待たせずに済み、オフラインでもそのまま取り込める。進み具合の表示・止める操作・オフラインのときの扱いを、新しく作らずに済む（取得待ちの処理がもう持っている）。
- **取り込んだ値を再取得でも守る**: 取得待ちの自動の再取得に任せるので、守らないと、オフラインで取り込んだ本や、取得が終わる前の本の CSV の値が、取得元の値に置き換わる（「CSV の値を優先する」に反する）。取り込むときだけ守る形は、ユーザーが選ばなかった。
- **登録日時を取り込む**: 他の蔵書アプリからの移行と、書き出しの取り込み直しで、登録日の並び順が残る。コアは作成日時を外から決められなかったので、作成の経路を 1 つ足した（同期の Op の形は変わらない）。
- **読めない値は項目だけ空にして行を取り込む**: 1 つの値（例えば日付の書き方）のために行全体を落とすと、直す手間が大きい。ISBN だけはエラーにする（重複の確認と書誌の取得の鍵で、空にすると重複や取り違えのもとになる）。
- **`ID` を書かない**: 取り込む本は新しい ID で作る。同じ ID を使うと、完全削除した本の ID と重なったり、別の蔵書の同期の履歴と混ざったりする。書き出しを同じ蔵書に取り込み直したときの重複の確認にだけ使う。
- **確認の画面を挟み、取り込めなかった行を保存できるようにする**: 元に戻す操作（0022 §2 であと回し）がないので、DB を変える前に結果を見せる。取り込めなかった行だけを保存して直せば、ISBN のない行を重ねて取り込まずに済む。
- **保管場所を自動で作る**: 取り込む前の確認の画面に、作る場所のパスを出すので、意図しない場所ができる前に気づける。

### あとでやってもよいこと

- 他のアプリの値の言い換え（読書状況の「読みたい」「積読」など）を画面で対応させる。
- 対応の記憶（同じ見出しの CSV を次に開いたとき、前の対応を使う）。
- タブ区切り（TSV）、UTF-16。
- 大量に取り込んだあとの取得の進み具合を、一括再取得（0027）の表示に載せる。今は、取得待ちの処理が裏で全冊を順に取り（その間、手動の再取得は待つ）、サイドバーの「取得待ち」で残りが分かるだけ。
