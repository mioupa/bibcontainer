# 0004: 端末 ID・HLC・変更ログ（Op）

## 状態

採用

## 日付

2026-10-14

## 背景

すべてのデータ変更を、同期を実装する前から Op として記録する（0 章 5）。同期（フェーズ 2）では、他端末の Op が順不同・重複・欠番ありで届いても全端末が同じ状態に収束する必要がある。そのため、Op の形式、時計、適用の規則を先に固める。

## 決定

- **端末 ID**: `d-` + 小文字 16 進 12 文字（乱数）。`:` を含まない。初回の `open` で生成して `local_meta.device_id` に保存し、以後は読むだけ。ライブラリ ID は、同期フォルダを設定するとき（フェーズ 2）に作る。エンティティ ID は UUIDv7（ハイフン付き小文字）。
- **HLC**: `{ミリ秒 15 桁}:{カウンタ 5 桁}:{device_id}`（ゼロ埋め）。文字列比較が論理順と一致する。パース時は桁数・数字・端末 ID を検証する。
  - ローカルの次の値: `ms = max(現在時刻, 前回の ms)`。ms が前回と同じならカウンタ +1、違えば 0。カウンタが 99999 を超えるときは ms を +1 してカウンタ 0。
  - 他端末の HLC を観測したら、(ms, counter) を `max(自分, 受け取った値)` にする（`observe_hlc`）。
  - 現在時刻は `Clock` トレイトで注入する（テストでは `ManualClock`）。
- **前回値と seq のカウンタ**: `local_meta` の `hlc_last`（`{ms}:{counter}`）と `op_seq_last` に持つ。変更を記録するのと同じトランザクションで読み書きする。
- **Op**: `{"v":1,"dev":..,"seq":..,"hlc":..,"ent":..,"id":..,"set":{..}}`（キーはこの順）。`ent` は `book` / `series` / `location` / `tag` / `shelf`。`set` は項目名の辞書順。`outbox.seq` は Op の `seq` そのもの（1 から）で、`op_json` は完成した Op の 1 行 JSON。
- **項目と型**: Text、Integer（i64）、Real、Bool（DB は 0/1、Op は true/false）、Json（配列かオブジェクト。DB には JSON 文字列）。Op 上の名前と列名が違うのは、books の `authors`→`authors_json`、`tags`→`tags_json`、`field_sources`→`field_sources_json`、`manual_fields`→`manual_fields_json`、shelves の `query`→`query_json`。同期する項目は、各テーブルの列のうち `id`、`extra_json`、`updated_at` 以外すべて。
- **`apply_op(tx, &op)`**（ローカルとリモートで共通）:
  1. 行がなければ `INSERT OR IGNORE` で id だけの行を作る。
  2. 項目ごとに、`field_clocks` の HLC が無いか Op の HLC の方が新しいときだけ、値と時計を書く（同じか古ければ何もしない）。
  3. 知らない項目名は `extra_json` の該当キーに入れる。時計の扱いは同じ。キーは辞書順で保存する。
  4. NOT NULL 列への null は、列の既定値を書く。NULL 可の列では NULL（値の消去）。
  5. 値の型が合わない項目は、その項目だけ無視する（時計も進めない）。警告ログを出す。
- **`record_change(tx, clock, ent, id, set)`**: まず検証する（未知の項目・型の不一致・NOT NULL 列への null・空の `set`・UUID でない ID はエラー）。次に HLC と seq を採番して保存し、`apply_op` で適用し、outbox に追加する。呼び出しごとにセーブポイントを張るので、失敗した 1 件だけが取り消される。
- **`updated_at`**: 端末ローカルの派生値で、同期しない。項目が 1 つでも書き換わったら `max(既存値, Op の HLC の ms を ISO 8601 UTC ミリ秒にしたもの)` にする。
- **要件書 8.2 からの変更**:
  - 同期対象テーブルの NOT NULL 列（`id` 以外）に DEFAULT を付けた。
  - books 以外にも `extra_json` を付けた。
  - `tags.name` の UNIQUE を外し、通常の索引にした。
  - 主キーの `id` に `NOT NULL` を付けた。

## 理由

- 前回の HLC を壁時計ではなく DB に持つので、再起動後に時計が戻っても HLC は逆行しない。記録と同じトランザクションなので、ロールバックすれば HLC と seq も戻り、欠番や飛びが残らない。seq を outbox の最大値ではなくカウンタで持つのは、書き出し済みの行を消しても seq を再利用しないため。
- 他端末の Op は欠番ありで届き、作成 Op より先に部分更新が届くことがある。DEFAULT があれば、`INSERT OR IGNORE INTO t(id)` だけで行を作れる。`extra_json` は、新しい版の端末が足した項目をすべてのエンティティで保持するため。
- 項目単位の LWW（厳密な `>` での比較）は、冪等で、順序に依存しない。削除も `deleted` 項目の LWW なので、ほかの項目の更新で削除が取り消されることはない（AT-S4）。型違いの項目を「無視して時計も進めない」としたのは、どの順で適用しても結果を同じにするため。
- `tags.name` が UNIQUE のままだと、2 台が同じ名前のタグを別 ID で作ったとき、取り込みで制約違反になり適用できなくなる。重複の扱い（統合など）はフェーズ 1 で決める。
- ローカルの記録を厳しく検証するのは、自分のコードの誤りを早く見つけるため。他端末の Op は寛容に受け入れる。

## 影響・今後

- フェーズ 2 は、他端末の Op を取り込むとき `observe_hlc` を呼ぶこと。呼ばないと、次のローカル変更が `ClockBehind` になる（黙って負けるより、エラーにして気づけるようにしてある）。他端末の時刻が 5 分以上未来のとき（FR-SYNC-11）は、観測する前に警告する。
- `ent` が未知の Op、`v` が 1 でない Op は、今の `Op` の読み込みでは扱えない。保留するか、スキップするかをフェーズ 2 で決める。
- 新しい版が、`extra_json` に入っていた項目を正式な列にするときは、マイグレーションで `extra_json` から列へ移す。時計は Op 上の項目名で `field_clocks` に入っているので、そのまま使える。
- `dump_canonical` は、収束の性質テスト（AT-S7）と JSON 書き出し（FR-IO-02）の土台。`updated_at` は含まない。
