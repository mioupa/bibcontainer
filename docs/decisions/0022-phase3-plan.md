# 0022: フェーズ 3 の範囲・順番・進め方

## 状態

採用（計画。2026-10-17 にユーザーと決めた。各機能の詳細は、機能ごとの決定記録に書く）

## 日付

2026-10-17

## 背景

フェーズ 0〜2 を実装し、フェーズ 2 の実機確認は S20（書影が数百冊以上ある蔵書での最初の同期）以外を終えた（`docs/acceptance/phase2.md`）。要件書 12 章のフェーズ 3（機能拡張）は項目が多く、受け入れ基準の表がない。そこで、実装を始める前に、範囲・順番・各機能の形をユーザーと決めた。実装は機能ごとの新しいセッションで行う。

## 決定

### 1. 範囲と順番

| 順 | 機能 | 要件 | ユーザーの決定・既定案 |
|---|---|---|---|
| 1 | 楽天ブックス | FR-META-02（[SHOULD]）、11.5、13 章 #4 | **アプリの登録（アプリ ID とアクセスキー）はユーザーがする。Referer は送らない。** 公式の仕様で、デスクトップアプリから Referer なしで呼べるかを最初に確かめ、Referer が要るなら楽天はやめる（理由を記録し、13 章 #4 を「見送り」にする案を出す）。呼べるなら実装する |
| 2 | キーワード検索 | FR-META-12（[SHOULD]） | 手動登録フォームに「書名・著者で探す」を置く。NDL・Google・Open Library（楽天を入れたら楽天も）を探し、選ぶとフォームに入れる。ISBN があれば、ふだんの取得で詳しい書誌を取り直す |
| 3 | 一括再取得 | FR-META-13（[SHOULD]） | 全件や、サイドバーの絞り込み（取得待ち・情報不足など）の本をまとめて再取得する。進み具合を表示し、途中でやめられる |
| 4 | グリッド表示 | FR-LIST-07（[COULD]） | 書影を並べる表示に切り替えられる。一覧と同じく、画面の外の画像は外す（0010 §14 のメモリの約束） |
| 5 | 巻をまとめた表示 | **要件書にない（新しく足す）** | **作品単位**（巻次を外した書名と著者が同じ本）で、**一覧の行を畳む**（「▶ スローループ（全 7 冊）」、開くと各巻）。まとめるかどうかは切り替えられる。シリーズ（レーベル・叢書名）ではまとめない |
| 6 | 汎用 CSV 取り込み | FR-IO-04（[SHOULD]） | 文字コードは UTF-8（BOM の有無とも）と Shift_JIS を自動で判定。列と項目の対応は画面で選ぶ。ISBN のある行は書誌も取り、CSV の値を優先する（由来は `import`）。登録済みの ISBN は飛ばす |
| 7 | PC カメラでの読み取り | FR-SCAN-20（[COULD]） | zxing-wasm（WKWebView は BarcodeDetector がないため。6 章の表）。スキャン登録画面で「カメラで読む」を切り替え、読んだ数字列はリーダーと同じ流れに渡す。macOS の `NSCameraUsageDescription`、Windows の WebView2 の権限 |

- 順番の理由: 楽天は、今の漫画・和書の書影が Google の 128 ピクセルなので効き目が大きく、取得元まわりの作業（0017〜0021）の続きでやりやすい。キーワード検索は楽天の有無で取得元が変わるので、楽天のあと。一括再取得も同じ書誌取得のコード（`crates/metadata`・`src-tauri/src/metadata`）を触る。グリッド表示と巻をまとめた表示は、どちらも一覧（`BookTable` のまわり）を触るので、この順に続けてやる。
- 1〜3 は同じコードを触るので順番に。4・5 は一覧、6 は入出力、7 はスキャン登録画面で、1〜3 とはほぼ重ならないので、並行してもよい（並行するときは、別の worktree で動かす）。

### 2. あと回しにしたもの（決定だけ記録する）

| 機能 | 要件 | 決まっていること |
|---|---|---|
| 元に戻す（⌘Z） | 9.5（[SHOULD]） | **何段も戻せて、やり直し（⇧⌘Z）もできる。** 起動している間の操作が対象（編集、ゴミ箱、まとめての編集、登録）。戻す操作も Op として記録し、他の端末に届く。他の端末がそのあと変えた項目は戻さない |
| スマート本棚 | FR-LIST-05（[SHOULD]） | **今の絞り込み（検索語とサイドバーの選択）に名前を付けて保存するだけ。** 評価や年で絞る条件の組み立ては作らない（要件書の例「読了・★4以上・2026年」は、この形ではそのままでは作れない。要件書の修正案が要る） |
| 集計 | FR-STAT（[SHOULD]） | 範囲から外した。形は要件書 7.7 のとおり |
| Amazon Creators API | 11.6、13 章 #2・#3 | 利用資格（直近 30 日で 10 件の紹介販売）を満たさないので、やらない |

### 3. 進め方（各セッション共通）

- 最初に `CLAUDE.md`、メモリ、この記録、関係する決定記録を読む。外部 API は、実装前に公式ドキュメントで確かめる（`CLAUDE.md`）。
- **受け入れ基準**: 要件書 12 章のフェーズ 3 には AT の表がない。各機能のセッションが、最初に AT の案（`AT-3x`）を作ってユーザーに見せ、承認を得てから実装する。要件書への追記も、案を見せてから行う。
- 設計は Opus、実装の重い作業は Sonnet のサブエージェントに任せる（ユーザーのグローバル設定）。機能ごとに決定記録を 1 つ書く（0023 から）。
- コミットと push は、`pnpm check` を通してから、区切りごとに確認なしでしてよい。push したら CI を確かめる（`CLAUDE.md`「コミット・push と指示の扱い」）。
- 実機で確かめることは、手順を書いてユーザーに頼む（日本語入力、カメラ、Windows など）。

### 4. 小さな残り（どのセッションでついでにやってもよい）

- どこからも参照されなくなった書影のファイルの整理（下書きだけで保存しなかった本の書影、再取得で替わった書影など。0010 §5・0021 §4 で「フェーズ 3」に回したもの）。
- 「このアプリについて」のクレジットを押せるリンクにする（外部のページを開くプラグインが要る。0017 §5）。
- Google の回避策の、実際のキーでの live テスト（0018。ユーザーの実機の再取得では動いている）。
- AT-09（日本語入力をオンにしたまま、手入力欄にフォーカスがある状態でのリーダーの読み取り。0012 §9）の実機確認。
- フェーズ 2 の S20（ダミーの蔵書で、書影つきの数百冊を用意して試せるかもしれない。`docs/acceptance/dummy-db/`）。

## 理由

- 範囲をユーザーが選んだ（「書誌まわり」「表示」「入力の拡張」。「操作と集計」はあと回し）。
- 巻を作品単位でまとめるのは、今のシリーズが取得元の都合でレーベル・叢書名（`Manga time KR comics. Kirara menu`、`岩波文庫`、`ジャンプ・コミックス`）になっていて、シリーズでまとめると作品ごとにならないため。
- 楽天で Referer を送らないのは、NDL の書影のとき（0007「改訂」）と同じく、アクセス制限を回避する形になりうる操作は避けるという判断。
