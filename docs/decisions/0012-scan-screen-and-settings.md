## 背景

フロントの基盤（0008: スキャン入力、ペアリング、通知音）と Rust 側の IPC（0009、0010: `classify_code`、`find_by_isbn`、`fetch_metadata`、`create_books_from_drafts`、設定、バックアップ、取得元）はできている。その上に、スキャン登録画面（9.3）と設定画面（FR-CONF）を作り、メイン画面を含めた 3 画面の切り替えをつなぐ。登録・編集フォームとメイン画面は別の担当が作る。担当の境界は、`src/stores/screenStore.ts`（画面の切り替え）と `src/stores/editorStore.ts`（フォームを開く口）の 2 つのストアである。

## 決定

### 1. 画面の切り替え（`src/App.tsx`）

- `useScreenStore` の `screen`（`main`／`scan`／`settings`）で、`MainScreen`・`ScanScreen`・`SettingsScreen` のどれか 1 つだけを描く。切り替えは、ストアの `showMain`／`showScan`／`showSettings` だけで行う。
- 画面の外側に、次を 1 つだけ置く。
  - `<EditorHost />`: DB が使えるとき（`AppShell`）に、画面と並べて置く。どの画面からも `useEditorStore` の `openNew`／`openDraft`／`openEdit` で開ける。
  - `<Toaster />`: エラー画面でも出せるよう、`Gate` の外（`App`）に置く。
- `useLibraryChangeSync()`（`library-changed` の購読）は、`MainScreen` から `AppShell` に移した。スキャン登録画面で保存した本や、設定画面で復元したデータが、メイン画面に戻ったときに古いまま残らないようにするため。画面ごとに購読すると、画面を切り替える間に通知を取りこぼす。
- 設定画面の表示する節は `useScreenStore` の `settingsSection`（`sync`／`providers`／`scan`／`display`／`price`／`backup`／`about`）。左の一覧で選ぶと `showSettings(section)` を呼ぶ。
- 暫定の `SettingsDialog` は削除した（`ja.settings.tabs` も同時に削除）。

### 3. 読み取りの流れ（`useScanFlow`）

```
useScanCapture（キー入力 → 数字列）→ classify_code（Rust）→ usePairing（2 段のペアリング）→ 効果の実行
```

- 数字列の判定（IPC）は非同期なので、`createSerialQueue` で読んだ順に判定し、ペアリングへ渡す。判定に失敗したら、エラー音と理由の通知（状態は変えない）。
- ペアリングの効果ごとの処理:

| 効果 | 処理 |
|---|---|
| `startLookup` | `fetch_metadata(isbn13)` を始める（2段目を待たない。FR-SCAN-05）。結果は ISBN ごとにストア（`lookups`）に入れる。同じ ISBN が進行中ならその結果を待ち、取得済みならそのまま使う（失敗・オフラインの結果は、次に読んだときに取り直す）。直前に読んだ本を、この ISBN にする（先に 2段目を読んでいれば、その値を引き継ぐ） |
| `sound` | `playSound`（成功・エラー・注意） |
| `message` | 結果の表示（文言は `ja.scan.message`、色はレベル）。2段目を保留したときは、直前に読んだ本に 2段目の値を出す |
| `confirm` | 確定した本の処理（下の 4）を、列に並べて 1 冊ずつ行う（フォームや確認を順に出すため） |

- フォームやダイアログ（`useEditorStore` の `request`、欲しい本の確認）を開いている間は、読み取り（`useScanCapture`）と確定キーを止める。
- 確定キー: スペースキー（`useCommitKey`）。テキスト入力欄、ダイアログ、メニューの中では拾わない。ボタンにフォーカスがあるときも拾い、そのボタンの操作にならないよう keydown と keyup の既定の動作を止める。画面上の「確定」ボタンも同じ。
- 手入力欄: 全角の数字を半角にして（`toHalfWidthDigits`）、同じ流れに渡す。`data-scan-target` は付けない（付けると、人が打つ数字を `useScanCapture` が奪う）。確定したらフォーカスを外し、リーダーを使えるようにする。
- 手入力欄以外の入力欄（共通値のタグ・購入日など）にフォーカスがあると、リーダーの数字がその欄に入る（0008 §8 の仕様）。そのため、画面にその旨を出し、共通値の入力欄は Enter でフォーカスを外し、選択欄（保管場所・所有状態）は選んだあとフォーカスを戻さない。
- 引き渡し（FR-SCAN-10）: 表示時に `takeHandoff()` で取り出したコードがあれば、読んだものとして同じ流れに通す。
- 連続のとき、画面を離れる時点で保留中の本があれば、確定して一覧に残す（読んだ本を失わない）。1 冊ずつのときは捨てる。

### 4. 確定した本の処理（`flow.ts` の `processConfirmed`）

`find_by_isbn` で重複を調べて分岐する（`decideConfirmed`）。ゴミ箱の本は無いものとして扱い、所有（`owned`）があれば欲しい本（`wanted`）より先に重複とする。

| 結果 | 1 冊ずつ | 連続 |
|---|---|---|
| 所有済み（FR-SCAN-17、AT-12） | 注意音と「所有済み: 書名 ／ 保管場所のパス」を表示する。フォームは開かない。「2 冊目として登録」ボタンで、フォームを開く（FR-BOOK-10） | 注意音。行を「重複」にして足す。既定では保存の対象から外す（行ごとに対象に戻せる） |
| 欲しい本（FR-SCAN-18、AT-13） | 注意音のあと「所有に移しますか？」と確認。移すなら `update_book` で `ownership` を `owned`（由来 manual）にする。購入日は、コアが今日の日付を入れる。新しい本は作らない。移さないなら何も変えない | 同じ（一覧には入れない） |
| それ以外（手放した本だけ、ゴミ箱の本だけ、未登録） | 取得の完了を待って、`openNew({ isbn13, secondTier, fetched })` を開く（FR-SCAN-13）。フォームが閉じるまで、次の本の処理を待つ | 取得を始めて、一覧に行を足す。同じ ISBN の行が一覧にすでにあれば、「重複」の行として足す |

- 重複を調べる `find_by_isbn` が失敗したときは、エラーを通知して、新しい本として続ける（重複の確認だけが止まる）。
- 手放した本（`released`）だけの ISBN は、新しい本として登録できる（買い直したものとして扱う）。要件書は触れていない点なので、判断として記録する。

### 5. 2段目の上書き（`applySecondTier`）

- 取得の結果（`fetch_metadata` の `draft`）は、ISBN を読んだ時点で取得を始めるため、2段目を含まない。確定したときに 2段目があれば、下書きの `c_code`・`list_price` を、由来 `barcode` で上書きする。2段目は、この 2 項目で最優先の取得元であるため（7.3 の優先順位）、上書きが正しい。`null` の値（価格が不明）は上書きしない。渡した下書きは書き換えない。
- フォームへ渡す取得結果（`fetched`）は、下書きに 2段目を重ねたもの（`withSecondTier`）にし、`secondTier` も別に渡す。編集フォーム側の `buildDraftBase` は「バーコードの値 → 取得の下書き」の順に重ねるので、2段目を重ねていない取得結果を渡すと、取得元の Cコード・価格が 2段目を上書きしてしまう。
- 連続登録の行は、ISBN・2段目と、取得結果を別々に持ち、行の下書きと保存する内容は、そのつど `applySecondTier` で導く。

### 6. 連続登録（FR-SCAN-14／15）

- **行の状態**（`rowStatus`）: 重複 → 「重複」。取得結果がなければ「取得中」。あれば下書きの `meta_status` で、`ok`＝完了、`partial`＝一部取得、`failed`＝取得失敗、`pending`＝取得待ち（オフライン）。`fetch_metadata` 自体が失敗した行は、ISBN と 2段目だけの下書き（`meta_status` が `pending`）にする。
- **オフライン・取得失敗でも保存できる**（FR-SCAN-16、AT-11）: 下書きの項目に `meta_status` が入っているので、`create_books_from_drafts` に渡すだけで、取得待ちのまま保存され、Rust が自動で再取得する。
- **共通値**（`BatchPresets`）: 保管場所、タグ（カンマ・読点・改行で区切る）、所有状態、購入日、購入店。入れた項目だけを `FieldChange`（由来 `manual`）にする。
  - 直していない行は、取得結果の下書きに共通値を重ねる（共通値が優先）。
  - 行を編集した（`openDraft` の `onDone` で下書きを受け取った）行は、行の内容を優先し、行にない項目だけを共通値で補う（行ごとに直した値を、共通値で消さない）。フォームを開くときは、共通値を `presets` として渡す。
  - 共通値は、保存したあとも残す（棚ごとに何回かに分けて登録するため）。
- **まとめて保存**: 保存の対象（`included`）の行を、`create_books_from_drafts` で 1 回で保存し、成功したら一覧を空にする（対象外の行も取り除く）。失敗したら一覧を残して理由を通知する。取得中の行が対象に 1 つでもあるあいだは保存できない（取得の完了を待つ。取得中の冊数を表示する）。重複から対象に戻した行は、取得を始める。
- 行の編集は、取得中は押せない。削除は 1 行ずつ。「一覧を空にする」は確認のダイアログつき。

### 7. ISBN 一覧の取り込み（FR-IO-03）

- 連続モードの「ISBN 一覧を読み込む」: `lib/dialog.ts` でファイルを選び、`parse_isbn_list` の `ScanCode[]` を `pairIsbnList` に通す。
- `pairIsbnList` は、`pairingReducer` に、**すべて同じ合成時刻（0）で**コードを渡し、最後に確定キー（commit）を送る。時刻が進まないので、行の間でタイムアウトしない（行数が多くても、タイムアウトが最短の 3 秒でも、ISBN の次の行の 2段目とペアになる）。2段目だけが残れば捨てる。雑誌・一般 JAN・不正な行、二度読み、捨てた 2段目は、「読み取れなかった行」として件数に数える。
- 確定した本は、連続登録と同じ処理（4 の「連続」）に、1 冊ずつ通す。音と直前の表示は出さない。取得は、前の取得が終わってから次を始める（`startLookup` の `serial`。取得元のレート制限は Rust 側が守る）。所有済みの本は重複の行になり、欲しい本は確認のダイアログが出る（連続登録と同じ流れ）。
- 終わったら、追加した冊数、重複の冊数、読み取れなかった行の数を通知する。

### 8. 設定画面の構成（`src/features/settings/`）

左に節の一覧（`SettingsSection`）、右に内容。節ごとのファイルは `sections/` にある。

| 節 | 内容 | 保存先 |
|---|---|---|
| 同期（FR-CONF-01） | 端末 ID（`app_info`）と「同期はフェーズ 2 で対応します」だけ | — |
| 取得元（FR-CONF-02、FR-META-03） | `list_providers` の一覧。取得元ごとの有効・無効、使用中か。API キー（`type="password"`。`set_api_key` で保存して入力欄を空に戻し、「設定済み」とだけ表示。削除ボタン）。Google はキーを入れるまで使われない旨。接続テスト（`test_provider`）。項目ごとの優先順位（矢印で並べ替え。2段目は本体価格と Cコードで先頭に固定）。User-Agent の連絡先 | `get/set_provider_settings`、OS のキーチェーン |
| スキャン（FR-CONF-03） | 末尾キー、先頭・末尾の余分な文字数、ペアリングのタイムアウト（3〜30 秒）、キー間隔の閾値、末尾キーなしの確定時間、音の種類ごとの有効・音量・試聴、ミュート | `useSettingsStore`（Tauri の中では `scan` セクション） |
| 表示（FR-CONF-04） | テーマ、フォント（空で OS の既定）、文字サイズ（12〜24）、一覧の列の表示（メイン画面の「列」メニューと同じ `tableStore`。書名は隠せない） | `useSettingsStore`（`display`）、`useTableStore`（`list`） |
| 価格（FR-CONF-05） | 税込の併記、税率（0〜100） | `get/set_price_settings`（キーはメイン画面の `usePriceSettings` と同じ `["price_settings"]`。保存すると、メイン画面の値も更新される） |
| バックアップ（FR-CONF-06、FR-IO-05、FR-IO-01／02） | 保存先（フォルダ選択、既定に戻す）、日次（1〜365）・週次（1〜52）の世代数、今すぐバックアップ、一覧（種類・日時・大きさ）と復元、フォルダを開く、CSV 全件と JSON 全データの書き出し | `get/set_backup_settings`、`manual_backup`、`restore_backup`、`export_csv`、`export_json` |
| このアプリについて（FR-CONF-07、9.4、10.6） | バージョン、端末 ID、DB の版とパス、各取得元のクレジット表記（`list_providers` の `credit`）、NDLサーチの API を使っている旨、ログフォルダを開くボタン | `app_info`、`open_logs_dir` |

- 復元は、確認のダイアログ（現在のデータは復元前のバックアップとして残すこと、端末 ID が新しくなることを説明）→ `restore_backup` → `reloadLibrary(queryClient)`（0009 §3）。
- 数値の入力は、欄を離れたとき（または Enter）に範囲に収めて確定する。範囲外の値は収めた値が欄に出る。
- クレジット表記は、取得元の一覧を読めないとき（ブラウザなど）も、同じ内容の固定の表記を出す。NDLサーチの API を使っている旨は、常に出す。
- Tauri の外（ブラウザの `pnpm dev`）では、IPC が必要な節（取得元・価格・バックアップ）は使えない旨を出す。スキャン登録画面も、読み取りと保存ができない旨を出す。

## 理由

- 確定した本の処理を `FlowDeps` に切り出したので、重複・欲しい本・フォーム・一覧の分岐を、DOM も IPC も使わず、偽の操作で速くテストできる。ペアリングの reducer と同様に、時刻や副作用を外から渡す形に揃えた。
- 書誌取得を ISBN を読んだ時点で始めるので、2段目は取得結果に含まれない。2段目を後から重ねる純粋関数にすれば、順序（ISBN → 2段目、2段目 → ISBN）に関わらず同じ結果になり、取得をやり直す必要もない。
- 一覧を空にする、画面を離れる、フォームを開く、といった「消える」操作の前に確認や保全を入れたのは、スキャンの途中で誤って本の入力を失うと、バーコードを読み直す手間がかかるため。
- ISBN 一覧の取り込みで時刻を合成するのは、ファイルの行が実時間で読まれるわけではなく、実時間を渡すと、行の間隔が T 秒を超えたときにだけペアが崩れて、結果が不安定になるため。
- 設定画面を画面（ダイアログではなく）にしたのは、取得元の優先順位やバックアップの一覧など、内容が多く、節で分けたほうが見やすいため。

## 影響・今後

### 要件書との差異（修正案。直接は直していない）

- 7.2 FR-SCAN-17／18: ゴミ箱の本と手放した本は、重複や欲しい本とは扱わず、新しい本として登録できるとした。
- 7.2 FR-SCAN-14: 連続登録の一覧に同じ ISBN がすでにある場合も、「重複」の行にして既定で保存しないとした（二度読みの取りこぼし防止）。
- 7.9 FR-IO-03: ISBN 一覧に欲しい本が含まれると、1 冊ずつ「所有に移しますか？」の確認が出る（連続登録と同じ流れ）。
- 9.3: 「確定」ボタンと、手入力欄、「2 冊目として登録」ボタンを足した。

### 他の担当への申し送り

- `MainScreen` が `useLibraryChangeSync()` を呼んでいれば、外してよい（`App.tsx` の `AppShell` が常に購読する。二重でも害はないが、取り直しが 2 回走る）。
- 編集フォームの `buildDraftBase`（`features/editor/draftBase.ts`）は「バーコードの値 → 取得の下書き」の順に重ねるので、取得の下書きに 2段目が入っていないと、取得元の Cコード・価格が 2段目を上書きする。スキャン登録画面は 2段目を重ねた取得結果を渡す（上の 5）ので問題ないが、別の呼び出し元ができたときは、`secondTier` を取得の下書きより後に重ねるほうが堅い。

### 未実施・未解決

- 実機（WKWebView、WebView2）での確認は未実施: バーコードリーダーでの読み取り、日本語入力がオンのときのスキャン（AT-09。`preventDefault` が効かない OS があっても、読み取りは `code` で足りる設計）、スペースキーでの確定、通知音、フォルダ選択・保存ダイアログ、フォルダを開く動作、フォントの見た目。
- OS のキーチェーンへの API キーの保存（0010 の未確認事項のまま）。
- 連続登録の一覧は、行数が多いと（数百行）仮想スクロールしない。ISBN 一覧の取り込みは数百件までを想定している。
- 状態の表示（`role="status"`）は、残り秒数の更新を読み上げ機能が拾う。必要なら、段階の変化だけを通知する形にする。
- 連続登録の「選んだ方法」は localStorage。ほかの端末設定と同じ `local_settings` に置くには、Rust の `scan` セクションに項目を足す（Rust の変更が要る）。
- 設定画面の「取得元」の優先順位に、既定へ戻す操作はない（Rust 側に既定を返すコマンドがない）。
