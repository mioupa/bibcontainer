# 0023: 楽天ブックスの取得元（見送り）

## 状態

採用（見送り。2026-10-17 にユーザーが承認し、「影響・今後」の要件書の修正案を要件書 0.6 に反映した）

## 日付

## 背景

0022 §1 の 1 番目。楽天ブックス書籍検索 API を書誌の取得元に加える前に、デスクトップアプリから **Referer を送らずに** 呼べるかを公式の仕様で確かめ、Referer が要るなら楽天はやめる、とユーザーが決めていた（0022 §1・§3。Referer を送らないのは、NDL の書影のとき（0007「改訂」）と同じく、アクセス制限の回避になりうる操作を避けるため）。期待していた効き目は、今の漫画・和書の書影（Google の幅 128 ピクセルが多い）を、楽天の `largeImageUrl` で大きくすることだった。

確かめたもの（すべて 2026-10-17 に取得）:

- 公式: 楽天ブックス書籍検索 API の仕様（https://webservice.rakuten.co.jp/documentation/books-book-search）、ご利用ガイド（/guide）、楽天ウェブサービス規約（/guide/rule。日本語の原文。最後の改定は 2012-06-28）、クレジット表示方法と注意（/guide/credit）、ヘルプ（https://webservice.faq.rakuten.net 。Cloudflare の確認があって curl では読めないので、ブラウザで記事一覧（47 件）を読んだ）、公式ブログ（https://rakuten-webservice.tumblr.com/ ）。
- 第三者の記事（新しいアプリ登録の画面はログインしないと見られず、公式の文書にアプリの種別の説明がないため）: kanaxx「楽天ウェブサービスのAPI移行にいち早く対応したのでメモしておきます」（2026-02-11）、n-shingo「楽天ウェブサービスのアプリケーションIDの取得方法（2026年版）」、psn.netbiz-member「2026年の楽天APIアップデートに伴う移行について」。

## 決定

### 1. 楽天ブックスは取得元に加えない

コードは何も変えない。参考の税込価格（`ref_price_incl`）は、openBD と NDL の税込の価格表記からも入るので残す（コメントの「楽天など」は、ついでのときに直せばよい）。

## 理由

1. **規約上の用途と保存の制限に合わない（いちばん大きな理由）。** 楽天の情報を使ってよいのは、楽天の商品を紹介して楽天の商品ページへリンクするためで、それ以外の目的での複製・改変は禁止されている。bibcontainer は、取得した書名のヨミ・判型・書影などを正規化（改変）して蔵書 DB に保存し続け、同期フォルダ経由で他の端末にも写す。これは用途から外れ、保存も 3 か月の上限を超える。書影はファイルとして取り込むので、なおさら合わない。個人だけが使うアプリであることも、第 10 条 (10)（閉じた環境での利用の禁止）に読める。
2. **Referer なしで呼ぶには、IP アドレスの登録が要る。** 「API/バックエンドサービス」はサーバーからの呼び出しを想定した種別で、送信元の IP を前もって登録する必要がある。自宅の回線の IPv4 は変わることがあり（IPv6 の回線の上で IPv4 を共有する方式では、なおさら）、Mac と Windows を別の場所で使えば、それぞれの IP の登録が要る。IP が変わるたびに 403 になり、楽天の画面で登録し直すことになる。Referer の偽装ではないので、ユーザーの決めた条件（Referer を送らない）には反しないが、使い続けるための手間が大きい。
3. **効き目が想定より小さい。** 公式の仕様では `largeImageUrl` は 200×200 ピクセルで、今の Google の 128 ピクセルより少し大きいだけ。Google の `zoom=0` が効く本（0018・0021）より小さい。URL の大きさの指定を書き換えて大きい画像を取るのは、仕様にない使い方で、改変の禁止にも触れうるのでしない。

## 影響・今後

- 0022 §1 の表の 1 行目（楽天ブックス）は、この記録で見送りとする。次のキーワード検索（0022 §1 の 2 番目）の検索先は、NDL・Google・Open Library になる（「楽天を入れたら楽天も」は要らなくなる）。
- 漫画・和書の書影を大きくする別の手段は、今回は調べていない。必要なら別の記録で検討する。
- ユーザーがそれでも楽天を使うと決めた場合に要ること（参考）: 「API/バックエンドサービス」で登録し、許可 IP アドレスに使う場所の IPv4 を登録する。IP が変わると 403 `CLIENT_IP_NOT_ALLOWED` になるので、設定画面の接続テストでその旨を出す。楽天の商品ページへのリンク（`itemUrl`）を詳細画面に置き、クレジットは規定の HTML（リンク）で出す（外部のページを開くプラグインが要る。0017 §5）。保存の 3 か月の上限と用途の制限には、どう作っても合わないので、規約上の懸念は残る。
