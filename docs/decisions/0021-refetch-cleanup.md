# 0021: 実機で見つかった取得結果の誤りの修正（巻次・古い値・書影の形・大文字の著者名）

## 状態

採用（2026-10-16。ユーザーが実機で見つけた誤りへの対応）

## 日付

2026-10-16

## 背景

0017〜0020 を入れたあと、ユーザーが実機で 5 冊（洋書 3、和書 2）を登録・再取得し、次の誤りを見つけた。

| 本 | 症状 | 原因 |
|---|---|---|
| Clean Code（9780132350884）、Fundamentals of Radiation Materials Science（9781493934362） | 巻次が `: pbk.` | NDL（CiNii 由来の洋書のレコード）が、製本の種類（`pbk.` はペーパーバック）を `dcndl:volume` に入れている。`dcterms:title` の末尾にも ` : pbk.` がある |
| スローループ 7（9784832274167） | 巻次が `1866` | openBD の NDL 由来のデータの `summary.volume` が、この本の巻ではなく、レーベル（Manga time KR comics. Kirara menu）の通し番号（ONIX の `Collection` の `PartNumber`）。本当の巻次 `7` は NDL の `dcndl:volume` にある。和書の順位ではシリーズ・巻次は openBD > NDL なので、`1866` が採用された |
| 上の 2 冊の `: pbk.` | 直したあとに「書誌を再取得」しても残る | 再取得は、取得元が値を返さなくなった項目を消さなかった（コアは取得元からの空の値を無視し、下書きには値のある項目しか入らない） |
| 科学者の自由な楽園（岩波文庫、9784003115220） | 書影が白地に文字の切れ端 | Google の `zoom=0` が、図書館がスキャンした本（volume `NKdLAAAAMAAJ`）で、本文の文字を切り取った 575×92 の PNG を返した。既知のダミー画像ではないので、書影として保存された。`zoom=1` は本物の表紙（128×181） |
| Fundamentals（9781493934362） | 著者が `GARY S. WAS` | 洋書の順位では著者は Google が先で、Google の値が大文字だけ。Open Library・NDL は `Gary S. Was` |

## 決定

### 1. NDL: 巻次と書名から製本の種類を除く

- 巻次（`dcndl:volume`）は、先頭の ISBD の区切り記号（`:`・`;`・`,`・`/`・`=`・`.`）を除き、` : ` で区切った部分のうち、製本の種類の語に**完全に一致する**ものを除く。何も残らなければ巻次なし（`: pbk.` → なし、`v. 1 : pbk.` → `v. 1`、`(pbk.)` → なし）。
- 製本の種類の語（大文字小文字を区別しない。末尾の `.` と括弧は任意）: `pbk`・`paperback`・`paper`・`hbk`・`hardback`・`hardcover`・`hard cover`・`hc`・`cloth`・`alk. paper`・`acid-free paper`・`lib. bdg`・`library binding`・`softcover`・`soft cover`・`spiral-bound`・`spiral bound`・`board book`・`ebook`・`e-book`（`normalize::BINDING_TERMS`）。
- 完全一致だけを除くので、`paperback edition`・`v. 2 pbk`・`pt. 2` は残る。副書名がちょうど `paper`・`cloth`・`hc` の本では、それが消える（実害は小さいとみた）。
- 書名も、末尾が ` : <製本の種類の語>` なら除いてから、書名と副書名に分ける。今の 2 件のフィクスチャでは、解析が使う `dc:title` の値にはもともと ` : pbk.` がなく（`dcterms:title` にだけある）、こちらは備え。
- 和書のレコードは変わらない（全フィクスチャの解析結果を前後で比べ、変わったのは上の 2 件の巻次だけだった）。

### 2. openBD: NDL 由来のデータでは、レーベルの通し番号を巻次にしない

- **NDL 由来かどうかの判定**: `onix.DescriptiveDetail.ProductForm` がないもの。ONIX 3.0 では必須の項目で、版元ドットコムのデータ（フィクスチャ 9784780802047）にはあり、NDL 由来の 7 件のフィクスチャにはない（`DescriptiveDetail` は `Collection`・`Contributor`・`TitleDetail` だけ）。
- NDL 由来のデータでは、`summary.volume` が、`Collection` の書名要素のうち `TitleElementLevel` が `"02"`（叢書の階層）の `PartNumber` と同じなら、巻次として使わない。`Collection` の `PartNumber` から巻次を補う処理も、NDL 由来のデータでは行わない（`summary.volume` が空でも `1866` を拾わないように）。版元ドットコムのデータは今までどおり。
- 結果: スローループは、巻次が NDL の `7`、書名は openBD の `スローループ 7` から巻次を除いた `スローループ`（0007 §5 の既存の規則）、シリーズは `Manga time KR comics. Kirara menu`（openBD）。ONE PIECE（9784088725093）は変わらない（書名 `One piece`、巻次 `巻1`、シリーズ `ジャンプ・コミックス`）。

### 3. 再取得: 取得元が値を返さなくなった項目を消す

- コアに `UpdateOptions.clear_stale` を足した（IPC には出さない。`serde`・`ts-rs` から外した）。これが真のとき、`Origin::Provider(X)` からの空の値は、その項目の今の `field_sources` が `X` で、手で直した項目でなく、今の値が空でないときだけ、項目を消す。値と `field_sources` の記録を、同じ Op で消す。`NOT NULL` の列（著者など）は列の既定値にする。`volume` を消すときは `volume_sort` も消す。
- 再取得（`refetch.rs` の `stale_clears`）は、次の条件をすべて満たす項目を消す: 今の値の取得元が取得元（手修正・2段目ではない）、**その取得元が今回の取得で「取れた」（`found`）**、統合の結果にその項目の値がない。取得元が失敗した・該当なし・無効のときは消さない（たまたま取れなかっただけかもしれないため）。
- 消す対象の項目: `title_kana`・`subtitle`・`authors`・`publisher`・`published_on`・`c_code`・`ndc`・`list_price`・`ref_price_incl`・`pages`・`size_text`・`language`・`description`・`volume`・`series_id`。**書名・ISBN・取得状態は消さない。** 書影は §4 の場合だけ消す。 手で直した項目は、「手で直した項目も上書きする」を選んでも消さない（上書きする値がないため）。
- 取得待ちの本の自動再取得も、同じ処理を通るので、同じように消す。
- 注意: NDL が欠けのあるレコードを返すようになると、NDL 由来の値が消えることがある（ほかの取得元にも値がないとき）。

### 4. 書影: 縦横比が書影としてあり得ない画像は使わない

- 自動の書影の取得（`acquire_cover`）で、デコードしたあと、高さ÷幅が **0.5 未満か 3.0 を超える**画像は書影として使わず、次の URL へ進む（`cover::is_usable_auto_cover`。0007 §8 の「長辺 40px 未満は使わない」と同じ場所・同じ扱い）。試した結果は、小さすぎる画像と同じ `placeholder`。0.5 と 3.0 ちょうどは使う。
  - 目安: ふつうの書影は 1.2〜1.6、正方形の絵本は 1.0、横長の絵本は 0.7 前後。岩波文庫の 575×92 は 0.16。
- 利用者が自分で入れる書影（ファイル・クリップボード・URL の取り込み）には、この規則をかけない。
- **再取得で、使えない書影を取り直す（0007 §8・0010 §9 の「書影がまだない本だけ取得する」を改める）**: 書影の取得元が取得元（`field_sources` の `cover_hash` が `manual`・`barcode`・`import` でなく、手で直した項目でもない）で、保存してある元の画像（`<covers>/<先頭 2 文字>/<hash>.jpg`）が今の規則（縦横比・最小の大きさ）で使えないと判定される本は、書影を取り直す。判定は画像のヘッダーだけを読む（`cover::stored_cover_dimensions`、`spawn_blocking`）。
  - 取り直して使える画像が取れたら、その取得元の由来で `cover_hash` を書く。どの URL も使えなければ、§3 の仕組み（`clear_stale`）で書影を消す。試した URL がすべて通信エラー（`offline`）なら消さない（あとで取り直す）。古いファイルは消さない（孤立したファイルの整理はフェーズ 3）。
  - 保存してある画像のファイルがない・読めない本は、判定できないので何もしない（同期で書影がまだ届いていない本を消さないため）。
  - 手で入れた書影は、「手で直した項目も上書きする」を選んでも触らない。
  - 取得待ちの本の自動再取得も同じ処理を通る（取得元由来の書影 1 枚ごとに、ヘッダーを 1 回読む）。

### 5. 大文字だけの著者名は、ほかの取得元の書き方を使う

- 統合（`merge`）で著者を選んだあと、選んだ著者名が「大文字だけのラテン文字」（漢字・かなを含まない、英字が 2 文字以上、小文字がない）なら、ほかの取得元の著者を、その行の優先順位の順に見て、照合キー（`normalize::latin_name_key`。0019 §8）が同じで小文字を含む名前があれば、その書き方に置き換える。役割・ヨミは選んだ著者のまま。`field_sources` も選んだ取得元のまま（書き方だけを借りる）。
- 見つからなければそのまま（勝手に先頭だけ大文字にするなどの推測はしない）。大文字だけでない名前は変えない。置き換えに使う名前は、漢字・かなを含まないものに限る。
- 「他の取得元の値」（`others`）は、置き換えたあとに作る。そのため、置き換えに使った取得元の値が、選んだ値と同じになって `others` から落ちることがある（Fundamentals の Open Library の `Gary S. Was`）。選ばれなかった取得元の大文字だけの値は、そのまま `others` に残る。
- 結果: Fundamentals は `Gary S. Was`（取得元は google）。登録済みの本は、再取得で値が変わるので書き換わる。

## 理由

- 巻次の欄の中身は、取得元によって意味が違っていた（製本の種類、レーベルの通し番号）。どちらも、取得元のデータの意味に沿って捨てるだけで、推測で巻次を作ることはしていない（スローループの `7` は NDL の巻次の欄の値）。
- 再取得で古い値を消すのは、取得の規則を直したときに、登録済みの本にも直した結果を届けるため。消してよいのは、その値を出した取得元に今回問い合わせて、値が返らなかったときだけに限った。

## 影響・今後

- 既存の本は「書誌を再取得」で直る（手動の再取得は通信する。0010 §9）。
- 巻次を、`volume_sort` が読めない値（`別巻` など）に変えたとき、古い `volume_sort` が残る（以前からの問題。この作業では直していない）。
- openBD の NDL 由来のデータの書名からは、製本の種類を除いていない（洋書は openBD にほぼないため）。
- Google の `zoom=0` で、ダミーとも本物とも違う画像が返る例（図書館がスキャンした本の文字の切れ端）があった。形で弾けないもの（縦長の別の画像など）が出てきたら、`zoom=0` の PNG を疑うなど、別の判定を考える。
