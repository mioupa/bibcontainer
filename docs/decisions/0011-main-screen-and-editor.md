## 背景

フェーズ 1 の画面のうち、メイン画面（9.1）の操作を実処理につなぎ、登録・編集フォーム（9.2）を作った。Rust 側の IPC（0009）、書誌取得（0010）、フロントの基盤（0008）はできている。フォームを開く口（`stores/editorStore.ts`）と画面の切り替え（`stores/screenStore.ts`）は、スキャン登録・設定の画面と共有するので、公開 API（関数名と型）は変えていない。Rust 側は変更していない。

## 決定

### 1. フォームの構成（`src/features/editor/`）

- `EditorHost`（App が 1 つだけ置く）が `useEditorStore` の request を見て、`BookEditorDialog` を開く。request ごとに作り直す（前の入力を持ち越さない）。
- 3 つのモード（`editorStore` の定義どおり）: `edit`（登録済みの本）、`new`（新しい本）、`draft`（連続登録の一覧の 1 行を保存せずに直す。OK で `onDone(NewBookDraft)`）。
- 5 つのタブ（9.2）: 基本、分類・保管、読書、購入、メモ。非表示のタブも描いたままにする（`forceMount`）ので、エラーの欄に、タブを替えてからフォーカスできる。
- react-hook-form と zod。値は入力欄の都合で文字列が中心（金額・ページ数も文字列）。コアに渡す値は `opValue` が作る。
- 読み込み: `edit` は `get_book_detail`（キー `book_detail_for_edit`。詳細ペインのキャッシュとは別。開くたびに最新を読み、`gcTime: 0`、あとから変わっても入力中の値は差し替えない）と `list_series` を待ってから描く。`new`・`draft` は元のデータが request にあるので、すぐ描く。保管場所・タグ・購入店・Cコード表・価格設定は、届いたぶんが context に反映される（待たない）。
- 閉じ方: Esc・×・「キャンセル」。変更があれば破棄の確認を出す。外側のクリック（通知の操作を含む）では閉じない。
- 保存は、ボタンか ⌘Enter（Ctrl+Enter）。一行の入力欄の Enter では保存しない（誤って保存しないため）。開いたら書名の欄にフォーカスする。
- 開いている間は、`useModalGuard` で「ダイアログが開いている」と数える（§10）。

### 2. 検証（`schema.ts`）

コアの規則（0006 §2、`library/validate.rs`）に合わせる。

| 項目 | 規則 |
|---|---|
| ISBN | 空は可。ハイフン・空白・全角を直し、ISBN-10 は ISBN-13 に直す。13 桁でチェックデジットが正しいこと |
| Cコード | 4 桁の数字（全角は半角に直す） |
| 日付（発行日・読み始めた日・読了日・購入日） | `YYYY`・`YYYY-MM`・`YYYY-MM-DD` の実在する日付 |
| 本体価格・支払額・ページ数 | 0 以上の整数（カンマ・「円」・全角を許す。`i32` の上限まで） |
| 評価 | 1〜5 |
| 著者 | ヨミ・役割だけで名前が空の行は不可。まるごと空の行は無視する |
| 書名 | **ISBN がなければ必須**。ISBN があれば空でもよい（取得待ちで保存できる。FR-SCAN-16）。コアは書名の空を許すが、ISBN のない本が書名なしで残るのを避けるため、フォームだけ厳しくした |

- サーバーの検証エラー（`kind: validation`、`入力が不正です（rating）: …`）は、項目名（Op の名前）からフォームの項目に結びつけ、その項目の下に出して、そのタブを開く。フォームにない項目のエラーは、フォーム下部に出す。

### 3. 保存の規則（`changes.ts`、`save.ts`）

**edit**

- 初期値から変わった項目だけを `FieldChange` にして `update_book` に送る。比べるのは、書式をコアと同じに直した値（前後の空白、全角、ISBN のハイフン、空の著者行）。書式の違いだけでは「変えた」ことにならない。変更がなければ何も送らず、閉じる。
- 由来は `{ kind: "manual" }`。ただし、**他の取得元の候補から選び、そのまま直していない項目は、その取得元の由来**（`provider`／`barcode`）にして、`overrideManual: true` を付ける。理由: 手で直した項目に取得元の値を選び直すとき、`manual` で書くと取得元の情報（NDL など）が失われる。`provider` の由来は、手修正済みの項目だと書かれないため、`overrideManual` で、その項目の手修正の記録を外して書く（選んだ項目だけが対象）。選んだあとに直したら、手入力になる。
- シリーズは名前で受け、保存のとき `find_or_create_series` で ID にして `series_id` を足す（名前を消したら `null`）。

**new**（`create_books_from_drafts`）

- 元のデータ（`NewBookSource`）の優先順位（後のものが前を置き換える）: 読んだバーコードの値（ISBN、2段目の Cコード・本体価格。由来は barcode）→ 取得結果の下書き（`fetched.draft`）→ 先に入れる値（`presets`）→ 既に直した下書き（`draft`）。その上に、フォームで直した値が重なる。
- フォームで直した項目は `manual`（または選んだ候補の取得元）。直していない項目は元の由来のまま。値を消した項目は `null`。シリーズも同じ（`seriesName` の名前と由来）。
- 巻次を直したら、元の `volume_sort` を捨てる（コアが新しい巻次から作り直す。古い数値を残さない）。
- 取得状態（`meta_status`）: **ISBN がなければ付けない**（取得するものがないので、`pending` にすると、自動の再取得が「対象外」を繰り返す）。ISBN があり、取得できていない（未取得・`offline`、または取得後に ISBN を直した）ときは `pending`（あとで自動で再取得される。AT-11）。取得済みなら下書きのまま。
- 同じ ISBN の本が登録済みなら警告し、確認のチェックを入れるまで保存できない（FR-BOOK-10）。ゴミ箱の本は重複とみなさない。手動登録（書誌を取得していない・ISBN がない）では、書名が 2 文字以上になったら（0.4 秒の遅延）`search_books` で、書名が似た本を候補に出す（FR-SCAN-19。同じ著者を先に、5 冊まで、出すだけ）。
- 保存したら、作った本を選ぶ（一覧に現れたら選択される）。

**draft**: 保存せず、同じ組み立てで `NewBookDraft` を作り、`onDone` に渡して閉じる。

- 書誌を取得し直す操作（new・draft の ISBN の横の「書誌を取得」）: `fetch_metadata` の結果を、**まだ直していない項目**（空のまま、または前の取得のまま）に入れ、元のデータと候補を差し替える。手で入れた値は変えない。
- `features/library/drafts.ts` の `toNewBookDraft`（スキャン登録が使う）は、そのまま残した。フォームは、元のデータの重ね方が違う（取得結果・先に入れる値・下書きの 3 層）ので、`buildNewBookDraft`（`changes.ts`）を使う。`draftToChanges` は共用する。

### 4. 候補の出し方（FR-META-05）

- 各項目の横に、値の取得元（`field_sources`。new は下書きの由来）を小さく出す。値を直すと「手入力」、候補を選ぶとその取得元になる。
- 他の取得元の値: `MetaMerged.fields` の「採用した値、他の取得元の値…」を、同じ値は 1 つにまとめて、項目の横のメニューに出す（今の値にはチェック）。候補が 2 つ以上あるか、1 つでも今の値と違うとき（戻せるように）だけ、メニューを出す。
- 候補の取り方: `new` は `source.fetched.merged`（フォーム内で取得し直したらその結果）。`edit` は、ISBN があれば `fetch_metadata`（キャッシュが効くので通信は通常起きない。10 分間は取り直さない）の `merged`。通信できなくても、編集はできる（候補が出ないだけ）。Tauri の外（モック）では取らない。
- Cコードは数字と名称を並べて出す（`0193　一般・文庫・日本文学、小説・物語`。Cコード表から）。本体価格は、設定が「税込を併記」なら、欄の下に `1,300円（税込 1,430円）` の形で出す（FR-CONF-05）。

### 5. 書影の差し替え（FR-COVER-05）

- 今の書影（なければ仮の表紙）と、次の操作（`import_cover_*` が返すハッシュを `cover_hash` として、保存のときに書く。取り込んだだけでは本は変わらない）。
  - ファイルを選ぶ（ダイアログ → `import_cover_file`）。
  - ウィンドウへのファイルのドロップ: Tauri 2 は既定でウィンドウのドロップを OS 側で受け、HTML の `drop` イベントでは `File` が届かない。`getCurrentWebview().onDragDropEvent` のパス → `import_cover_file`。フォームを開いている間だけ受け、どのタブでも効く。HTML の `drop` の `File` があれば、`import_cover_bytes`（ブラウザ用の保険）。
  - 貼り付け: ⌘V（Ctrl+V）で、クリップボードが画像だけのとき（文字を含むときは欄への入力を邪魔しない）、または「貼り付け」ボタン（`navigator.clipboard.read()`）→ `import_cover_bytes`（`Uint8Array` をバイナリのまま送る）。
  - 画像 URL の入力 → `import_cover_url`。
  - 取得元の候補（他の取得元の書影の URL）→ `import_cover_url`。採用された書影は、取得時にすでに保存してあるので、候補に出さない。
  - 「元の書影に戻す」。
- 対応する形式は、Rust が読める JPEG・PNG・GIF・WebP。ほかの拡張子のドロップは、理由を通知して無視する。
- 本として保存しなかった書影は、孤立したファイルになる（0010 のとおり、整理はフェーズ 3）。

### 6. 詳細ペイン（FR-LIST-06）

- 選ぶとすぐ、一覧用の行（`ListRow`）の項目を出し、`get_book_detail` が届いたら、参考税込価格（`ref_price_incl`）・内容紹介・大きさ・言語・読み始めた日・感想・新品中古・購入メモ・メモ・手で直した項目（項目名）を足す。`BookDetail` の項目は、出さないと決めたもの（内部の ID・並べ替え用の値・書影の画像・ゴミ箱と完全削除の状態・取得元の記録・未知の項目）以外すべて出す。項目を足したときに出し忘れないよう、`DetailPane.test.tsx` が `Record<keyof BookDetail, …>` で、項目ごとに「出す（項目名）」か「出さない（理由）」を決めている。別の本の詳細は使わない。詳細ペインを閉じている間は取得しない。詳細のキャッシュは `library-changed` で無効にする（`sync.ts`）。
- ボタン: 「編集」（`openEdit`）、「書誌を再取得」、欲しい本のときだけ「購入済みにする」。

### 7. 書誌の再取得（FR-META-13、AT-16）

- 詳細ペインのボタンと、右クリックメニュー（選んだ本をまとめて）から、確認ダイアログを開く。「手で直した項目も上書きする」のチェックは、**開くたびにオフ（既定）**。オフなら `refetch_books(ids, false)`（手で直した項目は上書きされない）、オンなら `true`。
- 結果は通知する（更新・変更なし・手で直した項目を残した数・通信できなかった・対象外・失敗。使える取得元がないとき・通信できなかったときは、その理由）。

### 8. 検索欄の ISBN（FR-SCAN-09）

- 検索欄で Enter を押したとき、文字列が ISBN なら、次のとおりにする。スキャン（バーコードリーダーが数字と Enter を打つ）でも、手入力でも同じ。入力しながらの絞り込み（`search_books`）は、そのまま続く。
- **日本語入力がオンのままスキャンしても、Enter 1 回で確定する**（`features/library/useSearchEnter.ts`）。日本語入力がオンだと、リーダーの数字は変換中の全角の数字になり、Enter は変換の確定に使われる（Chromium・WebView2: `isComposing` が true、`key` が "Process"、`keyCode` が 229。Safari・WKWebView: `compositionend` のあとに `keyCode` 229 の Enter が届く）。以前は変換中の Enter を無視していたので、もう 1 回 Enter が要った。方法: 変換を確定する Enter を見たら、確定が欄の値に反映されたあと（Chromium は `compositionend` の次のタスク、Safari は Enter の次のタスク）に欄の値を見て、**ISBN の形（`detectIsbnSearch`。全角の数字は NFKC で半角にする）なら、通常の Enter と同じ確定として扱う**。ISBN の形でなければ何もしない（普通の日本語入力は、変換を確定するだけ）。Enter を伴わない変換の確定（候補の選択など）、Enter から 500 ミリ秒をすぎた確定、間にほかのキーがあった場合は、確定として扱わない。数字キーを `code` で拾って半角で入れ、日本語入力に渡さない方法は取らない: `keydown` の `preventDefault` が変換に効くかは OS ごとに違い、効かない環境では全角と半角が二重に入るため。jsdom のテストまで。実機（WebView2・WKWebView）では、日本語入力のオンのまま読んで 1 回で移るかを確かめる。
- 判定は IPC なしの純粋関数（`detectIsbnSearch`）。数字・ハイフン類・空白・X だけ（先頭の「ISBN」と全角は許す）で、先頭が 978・979 の ISBN-13 か、正しい ISBN-10（ISBN-13 に直す）。2段目（`192…`）・一般 JAN・チェックデジット不一致・`2001-2010` のような数字の検索語は、ISBN ではなく、ふつうの検索のまま。
- 登録済み（ゴミ箱でない本）なら、絞り込みと検索語を外して、その本を選ぶ（`useSelectionStore.reveal`。一覧がその本までスクロールする。**詳細ペインが閉じていれば開く**。すでに選んでいる本でも、一覧は動く）。ゴミ箱にだけあれば、ゴミ箱を開いてその本を選び、通知する。未登録なら「登録しますか？」と確認し、「登録する」で `showScan(ISBN-13)` に引き渡す。キャンセルなら何もしない。
- 登録済みかは、読み込み済みの一覧で調べる（IPC なし）。

### 9. メイン画面でのスキャン検出（FR-SCAN-10）

既存の `useScanCapture`（`mainScreen`）の検出を `showScan(数字列)` につなぐ。ダイアログ（フォームを含む）を開いている間は検出しない。判定（`classify_code`）はスキャン登録画面が行う。

### 10. 一括変更と右クリックメニュー（FR-BOOK-08）

- メニュー: 編集／一括変更（読書状況・所有状態・評価（★1〜5、評価なし）・保管場所を変更…・タグを追加…・タグを外す…）／購入済みにする（欲しい本を選んでいるときだけ。欲しい本だけが対象。購入日が空なら、コアが今日を入れる。FR-WISH-01）／書誌を再取得…／CSV に書き出し…／ゴミ箱へ移動。
- 読書状況・所有状態・評価は、1 項目を手入力として `update_books` で書く。保管場所・タグは、値を選ぶダイアログ（保管場所は階層つきの選択、タグは候補つきの複数入力、外すのは選んだ本に付いているタグのチェック）を開き、保管場所は `update_books`（`location_id`）、タグは `modify_tags`（足す・外す）。タグを外すとき、`研究` を選んでも `研究/SiC` は外れない（名前が完全に一致するものだけ）。
- 価格の列は、設定が「税込を併記」なら併記する。

### 11. サイドバーの管理

- 保管場所: 見出しの「＋」で最上位に作成。項目の「…」ボタン（と右クリック）から、子の保管場所の追加・名前の変更・移動（自分と子孫は移動先に出ない。「最上位」へも移せる）・削除（確認つき）。子や本（ゴミ箱の本を含む）がある保管場所の削除は、コアが `conflict` で断る。その旨と、何をすればよいかをダイアログに出す。絞り込み中の保管場所を削除したら、絞り込みを外す。
- タグ: 名前の変更（`rename_tag`。子孫もまとめて変わる旨を案内する。空・空の階層ができる名前・同じ名前は送らない）と、色の設定。絞り込み中のタグを改名したら、新しい名前で絞り込み続ける。色は、**Catppuccin のアクセント色の名前**（`rosewater`〜`lavender`、仮の表紙と同じ 14 色）を `set_tag_color` で保存し、表示は `var(--ctp-<名前>)`（ライト・ダークで切り替わる）。サイドバーのタグの前に点で出す。知らない色の名前は、色なしとして扱う。
- 保管場所の並べ替え（`reorder_locations`）は、画面を作っていない。

### 12. ショートカット（9.5）

- **効く範囲**: ⌘N 手動登録、⇧⌘N スキャン登録、⌘, 設定は、**どの画面でも**効く（`useGlobalShortcuts`。App の `AppShell` が 1 度だけ呼ぶ。フォーム・ダイアログを開いている間は止める）。⌘F 検索欄、⌘I 詳細ペインは、メイン画面だけ（`MainScreen` が `useShortcuts` で受ける）。Enter 編集、⌘⌫（Windows は Delete）ゴミ箱は、一覧にフォーカスがあるときだけ（`BookTable`）。以前は 5 つとも `MainScreen` だけで受けていたので、スキャン登録画面・設定画面では、⌘N などが効かなかった。「元に戻す」（⌘Z）は、機能がないので、割り当てを使わない（以前の「未実装」の通知は外した）。
- フォームやダイアログを開いている間は、画面全体のショートカットとスキャン検出を止める。ダイアログを持つ部品が `useModalGuard(open)` で、開いているダイアログの数（`useModalStore`）を数え、App とメイン画面は `useAnyModalOpen()` を見る。どの画面でも効くようにしたので、数える部品を、スキャン登録画面の「所有に移しますか？」と「一覧を空にする」の確認、設定画面のバックアップの復元の確認にも足した（ダイアログを足すときは、`useModalGuard` を呼ぶこと）。一覧向けのキー（Enter・⌘⌫）は、ダイアログがフォーカスを持つので、一覧には届かない。
- **Tauri のメニューにキーを取られないか**: Tauri 2.12.3 の既定のメニュー（`Menu::default`）のアクセラレータは、macOS は ⌘C・⌘X・⌘V・⌘Z・⇧⌘Z・⌘A・⌘M・⌘W・⌘Q・⌘H・⌥⌘H・⌃⌘F、Windows は Ctrl+C・X・V・Z・Y・A など。⌘N・⇧⌘N・⌘F・⌘I・⌘,・Enter・⌘⌫ とは重ならない（ソースで確認）。重なるのは ⌘Z（Undo）だけで、アプリは使っていない。このアプリはメニューを作っていない。macOS の WKWebView が、メニューにないキーを JS に渡すかと、Windows の WebView2 の既定のブラウザのキー（Ctrl+F の検索など）を JS の `preventDefault` で止められるかは、実機で確かめる。

### 13. 価格の設定の読み込み

`usePriceSettings`（TanStack Query、キー `["price_settings"]`、`staleTime: 0`）。メイン画面を開くたびに取り直す。設定画面は別の画面なので、戻ってきたとき（メイン画面が作り直される）に反映される。設定を保存したときに、同じキーを `invalidateQueries` してもよい。

### 14. モック（Tauri の外）

`libraryApi`（`features/library/api.ts`）に、詳細・更新・タグの一括変更・下書きからの作成・ISBN の重複・購入店・価格設定を足し、モックでも動くようにした（`dev/mockBackend.ts`）。Rust が要る操作（書誌取得・再取得・書影の取り込み・シリーズ・保管場所とタグの管理）は、`mockUnavailable` が断り、通知で理由を出す。

### 15. 表示中の絞り込み結果の書き出し（FR-IO-01）

- 一覧の上の細い帯（「列」メニューの左）に、「表示中の N 冊を CSV に書き出す」ボタンを置いた（N は、今の絞り込み・検索・ゴミ箱の表示で一覧に出ている冊数）。`export_csv(path, ids)` に、一覧に出ている行の ID を並びのまま渡す。保存先を選んでやめたら何もしない。表示中の本がなければ押せない。「選んだ本」（右クリックメニュー）と「全件」（設定の「バックアップ」）は、今までどおり。

### 16. 一覧のスクロール（選択行へ戻さない）

- `BookTable` は、focus した行までスクロールする（キーボード操作・クリック・検索欄の ISBN）が、動かすのは **focus が変わったとき（と `reveal` で選び直したとき）だけ**。以前は行の配列が差し替わるたび（`library-changed` で行が更新されたときなど）にも動いていて、ユーザーがスクロールした位置から選択行へ引き戻していた。focus した行がまだ並びにないとき（絞り込みの更新より先に focus が変わる検索欄の ISBN など）は、「スクロール待ち」にして、並びに現れたときに 1 度だけ動く。

### 17. 列の並び順（FR-LIST-01）

- 0008 §6。「列」メニューは、並び順を変える矢印のボタンを持つので、ポップオーバーにした（チェックで表示・非表示、上・下の矢印で 1 つずつ。見出しのドラッグでは動かせない）。端末ごとに `list.columnOrder` へ保存する。

## 理由

- 手で直した項目を取得元の候補で置き換えるときだけ `provider` の由来にしたのは、取得元の記録（どの取得元の値か）を残すため。`overrideManual` は、選んだ項目の手修正の記録を外すだけで、ほかの項目に影響しない（`manual` の変更は常に書かれる）。
- ISBN がない本を `pending` にしないのは、再取得が ISBN のない本を対象外として飛ばし続け、サイドバーの「取得待ち」にも残り続けるため。
- 検索欄の ISBN の判定を IPC なしにしたのは、スキャン直後の Enter で通信を待たず、モックでも動かすため。判定の規則は Rust（`barcode`）に合わせた。2段目（`192…`）を ISBN としないよう、978・979 の接頭辞を要求する。
- フォームの値を文字列にして、変換と比較を `opValue` に集めたのは、検証（zod）・差分・コアへの値で、同じ正規化を使うため。
- 非表示のタブを描いたままにしたのは、エラーのある欄にフォーカスし、`register` した欄が外れないようにするため（react-hook-form）。
- 保管場所・タグの管理を、サイドバーの「…」メニューにしたのは、右クリックだけでは見つけにくいため。

## 影響・今後

### 未解決・今後

- 実機の確認が必要な操作は、報告に一覧がある。
- タグの色は、アクセント色の名前で保存する（同期するので、将来のモバイルが 16 進の色を期待するなら、変更を提案する）。
- 保管場所の並べ替え（`reorder_locations`）、書影の回転と切り抜き（FR-COVER-06、COULD）、書名・著者のキーワード検索（FR-META-12、SHOULD）は、作っていない。
- ISBN の横の「書誌を取得」は、依頼にはなかった小さな追加（手動登録で ISBN を入れたとき、同じ画面で取得できるようにした）。
- 設定画面で価格設定を保存したとき、メイン画面を開いたままの別ウィンドウには反映されない（ウィンドウは 1 つなので、画面を戻ったときに反映される）。
- `edit` で ISBN を直しても、取得元の候補は元の ISBN のまま（フォームを開き直すと更新される）。
- 要件書の修正は提案しない。FR-META-05 の「選び直せる」は、選んだ値を取得元の由来で保存する、と解釈した（§3）。
