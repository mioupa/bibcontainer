# 0024: 一覧のグリッド表示と、巻をまとめた表示

## 状態

採用（2026-10-17 にユーザーが設計と受け入れ基準の案を承認した。jsdom のテスト、ブラウザのモックとアプリ（書影つきのダミー 5,000 冊）でのスクロールとメモリの計測まで。実機での見た目と操作は未確認）

## 日付

2026-10-17

## 背景

0022 §1 の 4 番目（グリッド表示。FR-LIST-07 [COULD]）と 5 番目（巻をまとめた表示。要件書になかった新しい機能）。どちらも一覧（`BookTable` のまわり）を触るので、続けて作った。

巻をまとめる単位は、0022 のとおり**作品**（巻次を外した書名と著者が同じ本）にした。今のシリーズは、取得元の都合でレーベル・叢書名（`Manga time KR comics. Kirara menu`、`岩波文庫` など）になっていて、シリーズでまとめると作品ごとにならないため。漫画の書名は、統合の最後に巻次を外している（`crates/metadata/src/merge.rs` の `strip_volume_from_title`。`スローループ 7` → 書名 `スローループ`、巻次 `7`）。ただし、openBD だけで取れた本（書名が `スローループ 7` のままで巻次が空）や、それより前に登録した本・手で入れた本は、書名に巻次が残っている。そのため、まとめるときは画面の側でも末尾の巻次を外す。

受け入れ基準は、承認された案（AT-30〜AT-35）を要件書 12 章のフェーズ 3 に入れた。

## 決定

### 1. 切り替えと保存

- 一覧の上の帯の左に「表｜グリッド」の切り替え（`ViewSwitch`）と「巻をまとめる」のボタン（`GroupToggle`。押した状態を持つ）を置いた。右は今までどおり「表示中の N 冊を CSV に書き出す」と、表では「列」、グリッドでは「並べ替え」（`SortMenu`）。
- 端末ごとに、`local_settings` の `list` に `viewMode`（`"table"`／`"grid"`。既定は `"table"`）と `groupVolumes`（既定は `false`。今までどおりの表示）を保存する。Rust の `ListSettings`（`src-tauri/src/settings.rs`）と、フロントの `layoutStore`。壊れた値は、その項目だけ既定に戻す。
- 作品を開いているかどうかは、起動している間だけ覚える（`groupStore`。保存しない）。

### 2. グリッド表示（FR-LIST-07）

- `src/features/list/BookGrid.tsx`。表と同じ props（`ListViewProps`）を受け、同じ選択（`selectionStore`）、同じ右クリックのメニュー（`ListContextMenu.tsx`）を使う。共通の動き（Enter・ゴミ箱のキー・⌘A・Esc、クリックの修飾キー、右クリックの対象の行、選択行へのスクロール（0011 §16）、絞り込みで消えた行の選択の整理）は `useListInteraction.ts` に分け、表とグリッドの両方が使う。
- カードは幅 8rem・高さ 15rem（書影は幅 7rem、縦横比 5:7。その下に書名を 2 行まで、巻次と著者を 1 行）。rem で決めるので、文字サイズの設定（FR-CONF-04）で書影も一緒に大きくなる。仮想スクロールの行の高さは、`<html>` の文字サイズ（`useRootFontSize`）を掛けて px にする。
- 列の数は、スクロール領域の幅から決める（`gridColumnCount`。初めは `clientWidth`、そのあとは `ResizeObserver`）。幅を測るまでは行を作らない（列の数が違う並びで「スクロール待ち」が解かれて、行き先がずれるのを防ぐ）。
- 行（カードの段）を TanStack Virtual で仮想化する（前後 3 段を余分に描く）。画面の外のカードと書影の `<img>` は DOM にない。
- 矢印キーは 2 次元で動く（`gridLayout.ts` の `gridMove`。純粋関数）。←→ は前後のカード（段をまたぐ）、↑↓ は上下の段の同じ位置（段が短ければ、その段の最後）。Home・End は最初・最後、PageUp・PageDown は見えている段の数だけ。Shift で範囲を広げる。キーで動かすときの選択は `moveFocusTo`（`selection.ts`）。普通のクリックの範囲選択（`clickRow`）とは、起点がないときの扱いが違う（クリックは押した行、キーは今の focus か最初の行）ので分けた。`moveFocus`（表の上下）は `moveFocusTo` を使う形に直した（動きは変えていない）。
- 並べ替えは、見出しがないので、帯の「並べ替え」で列（並べ替えできる列）と向きを選ぶ。選ぶと並べ替えを 1 列にする。状態は表と共通（`tableStore.sorting`）。
- ARIA は `grid`（段が `row`、カードが `gridcell`、`aria-selected`）。

### 3. 書影のサムネイルは、どの大きさも `no-store`

- グリッドの書影は、2 倍の画面でぼけないよう、長辺 320px のサムネイル（`GRID_COVER_SIZE`）を使う（幅 7rem の枠は、2 倍の画面で 224 × 314 px）。
- 0010 §14 では、一覧用の 80 だけを `no-store` にし、詳細ペイン・フォームの 320 は `immutable` だった。WebKit は、読み込んだ画像を `<img>` が外れたあともメモリキャッシュに持ち続ける。グリッドは 320 を何千冊ぶんも見せるので、320 を残させるとメモリが増え続ける。
- そこで、**サムネイル（80・160・320）はすべて `no-store`、原寸だけ `immutable`** にした（`src-tauri/src/metadata/cover_protocol.rs` の `cache_control_for`）。書影は端末内のファイルで、読み込みは 1ms 未満。詳細ペインの 320 も、本を選び直すたびに読み直すことになるが、1 枚なので無視できる。

### 4. 作品の判定（`src/features/library/works.ts`）

行ごとに次を求め、行のオブジェクトごとに覚えておく（`WeakMap`。行は変わったときに差し替わる）。

- **巻次を外した書名**（画面に出す形）。元の書名から、末尾の巻次を 1 つ外す。
  1. 巻次の欄に値があり、書名がそれで終わる（直前が空白か `.`）なら、それを外す（`スローループ 7` ＋ `7`、`One piece 巻1` ＋ `巻1`）。統合の `strip_volume_from_title` と同じ規則で、それより前に登録した本のため。外したあとに `vol`・`No`・`#`・`第`・`巻` が残れば、それも外す（巻次が `7` で書名が `X vol.7` の本と、書名が `X` の本を同じ作品にするため）。
  2. そうでなければ、次の形を外す（全角・半角とも。英字の大小は区別しない）。
     - 空白のあとの番号: `7`、`第7巻`、`7巻`（`集`・`部`・`編` も）、`vol.7`、`Vol 3`、`No.2`、`#5`、`巻1`、`第三巻`
     - 括弧の番号: `（7）`、`(7)`、`[7]`
     - 空白のあとの `上`・`中`・`下`・`上巻`・`中巻`・`下巻`・`前編`・`後編`
  3. 空白のない形（`坂の上`、`1Q84`、`ムーミン谷の十一月`）は外さない。外すと空になるとき（`第1巻` だけの書名、`1984`）も外さない。
- **書名から外した巻の数**: 巻次の欄が空で、2 で外したときだけ（漢数字は数に直す。上・前編は 1、中は 2、下は 3、後編は 2）。作品の中の巻の順に使う（openBD だけの `スローループ 8` が 8 巻目に並ぶ）。
- **比べるための書名**: 巻次を外した書名を、NFKC → 小文字 → カタカナをひらがなに → 空白と中黒（`・`・`･`・`·`）を除く、の順に正規化したもの。空なら作品にしない。
- **比べるための著者名**: 著者ごとに、NFKC → 小文字 → 空白・中黒・`,`・`，`・`、`・`.` を除く。

副書名は比べない（ライトノベルの巻ごとの副題が違ってもまとまる）。シリーズ（`seriesId`）も使わない。

### 5. まとめ方（`src/features/library/grouping.ts`）

- 入力は、絞り込み・検索・並べ替えを済ませた行（`useLibraryView` の `rows`）。**表示中の本だけでまとめる**。
- 比べるための書名が同じ本を集め、その中で、著者が 1 人でも共通する本どうしを同じ作品にする（つながりをたどる。巻によって「原作・作画」の載り方が違っても、まとまる）。著者のない本は、同じ書名の作品が 1 つだけならそこに入れる。著者のある本がなければ、著者のない本どうしで 1 つの作品にする。作品が 2 つ以上あれば、どれにも入れない。
- 表示中に 2 冊以上ある作品だけを畳む。1 冊なら普通の行。
- 作品の置き場所は、今の並べ替えで、その作品のいちばん前に来る巻の位置。作品の中は、巻次の数（`volumeSort`、なければ書名から外した数）の順。数のない巻は最後で、同じ数なら今の並べ替えの順。
- 作品の鍵は `work:` ＋ 比べるための書名 ＋ 区切り ＋ 作品の中でいちばん小さい著者名（本の ID とは重ならない）。開いているかどうかは、この鍵で覚える。
- まとめないときも、同じ形（すべて普通の本の行）で返し、表とグリッドの描き方を 1 つにした。

### 6. 畳んだ行（表）

- 書名の欄: ▶（開いていれば ▼）のボタン、巻次を外した書名（最初の巻のもの）、冊数（「7 冊」）。絞り込みで減るので「全」は付けない。2 行目は、全巻が同じシリーズならシリーズ名。
- 書影: 最初の巻の書影に、後ろに 1 枚重ねた見た目。
- 巻次の列: 最初と最後の巻（「1〜7」。1 つしかなければその値）。
- ほかの列: 全巻が同じ値（並べ替えのキーで比べる）ならその値、違えば空。
- 開くと、各巻が字下げして出る。
- 「N 冊中 M 冊を表示」は冊数のまま。「表示中の N 冊を CSV に書き出す」は、表示の順（作品の中は巻の順）に全巻を書き出す。

### 7. 選択とキー操作

- 選択は、表示の単位（作品の行と本の行）の鍵で持つ。作品の行を選ぶと、その作品の全巻を選んだことになる。冊数や操作が要るところ（ステータスバーの選択数、詳細ペイン、右クリックの一括変更・再取得・書き出し・ゴミ箱、ゴミ箱のキー）では、`expandToBookIds` で本の ID に広げる。
- 詳細ペインは、作品の行に focus があるとき「N 冊を選択中」を出す。右クリックの「編集」は、作品の行では使えない。
- 表のキー: → は、畳んだ作品なら開き、開いていれば最初の巻へ。← は、開いた作品なら畳み、巻の行なら作品の行へ。Enter とダブルクリックは、作品の行なら開閉、本の行なら編集。ほかのキー（Shift+矢印、Home・End、PageUp・PageDown、⌘A、Esc）は表示の単位の上で今までどおり。
- グリッドのキー: 矢印は 2 次元の移動のまま（開閉には使わない）。Enter・ダブルクリック・冊数の札のクリックで開閉する。
- 選んでいる巻を含む作品を畳むと、その巻の選択と focus を作品の行に移す。
- 畳んだ作品の中の本に focus が来たら（検索欄の ISBN、登録した直後など）、その作品を開く。選択の整理より先に開くよう、まとめる処理は、focus のある本の作品を開いたものとして扱い、そのあと開いた状態を保存する。
- まとめるのをやめると、選んでいた作品の行は、その全巻の選択に置き換える（focus は最初の巻）。
- まとめているときの表は `treegrid`（行に `aria-level`、作品の行に `aria-expanded`）。

### 8. グリッドでのまとめ方

- 作品は 1 枚のカード（最初の巻の書影を重ねた見た目、書影の角に冊数の札、書名、「7 冊 · 1〜7」）。カードに `aria-expanded`。
- 開くと、その作品の巻が**次の段から**、薄い色の帯の中に並ぶ。作品のあとの本は、また新しい段から始まる（`layoutGrid` が、帯の段を分けて作る）。

### 9. ダミーデータ

- `docs/acceptance/dummy-db/` に `--works` を足した。同じ作品の巻（書名と著者が同じ。2〜40 巻）を約 3 割作り、そのうち 1 割は書名に巻次を含めて巻次を空に、5% は `書名（n）` にする。付けなければ、これまでと同じデータになる（引数なしの出力が変わらないことを、200 冊・5,000 冊で確かめた）。
- `src/dev/mockRows.ts`（ブラウザの `pnpm dev` と性能のテスト）も、約 25% を作品の巻にした。

## 理由

- 判定を画面の側に置いたのは、まとめるかどうかが表示の設定で、DB や Op に持つものではないため。2 万冊でも、まとめる処理は性能の目標（50ms）に収まる（「影響・今後」の測定）。
- 著者を「1 人でも共通」で比べるのは、取得元によって著者の載り方（原作・作画の有無、区切り、ヨミ）が巻ごとに違うため。書名だけでまとめないのは、同名の別の作品（`はじめての〜` など）を混ぜないため。
- 選択を表示の単位で持つと、Shift の範囲選択や矢印の移動が、今の `selection.ts` のまま、作品の行と本の行の両方で動く。本の ID が要るところだけで広げればよい。
- グリッドで開いた巻を次の段から帯の中に並べるのは、続けて並べると、どこまでが作品の巻か分からないため。

## 影響・今後

### 性能（詳しくは `docs/acceptance/phase3.md` 2 章）

- まとめる処理（`perf.test.ts`、2 万行、最速の回）: 行ごとの作品の情報が計算済みなら 8.9ms、全行が新しければ 24.2ms。開いている作品だけを変えるとき（`layoutEntries`）は 0.1ms。
- アプリ（リリースビルド、書影つきのダミー 5,000 冊、60Hz の画面）: 表・まとめた表（畳む・開く）・グリッド・まとめたグリッドのどれも、スクロールで 25ms を超えるフレームがなかった。DOM の `<img>` は最大 40 枚。
- メモリ（物理フットプリントの合計）: グリッドで全冊の書影を流したあとの落ち着いた値は 186MB（表は 190MB）。描画中の最大は表より 15〜25MB 高く、3 回のうち 2 回で目標の 300MB を数 MB 超えた（302MB・305MB）。**数 MB の超過は許容する**（ユーザーの判断）。前後に余分に描く段（`OVERSCAN_ROWS` = 3）を減らせば下がる見込みだが、測っていない。

### 未確認

### あとでやってもよいこと

- 作品の行に focus があるとき、詳細ペインに作品のまとめ（書影、巻の一覧、読んだ巻の数）を出す。今は「N 冊を選択中」。
- 表とグリッドの切り替え、巻をまとめるかどうかを、設定画面の「表示」にも置く。
